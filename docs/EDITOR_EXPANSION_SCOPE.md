# 에디터 확장 작업 범위

작성일: 2026-10-16  
기준 커밋: `51552a7`  
상태: 사용자와 정리한 구현 전 작업 범위. 이 문서의 추가 기능은 아직 구현되지 않았다.

## 목적과 기준

로컬에서 안정적으로 사용할 수 있는 에디터를 완성한다. 기존 선택·배선·이동·회전·삭제를 유지하면서 아래 기능을 단계적으로 확장한다. 구현 기준은 `CIRCLITH_MASTER_SPEC.md`이며, 구현 단계에서 해당 명세의 상태·관련 결정을 함께 갱신한다. 이 계획을 기록하는 커밋은 기능 구현, 브랜치 병합 또는 배포 정책 변경을 포함하지 않는다.

## 작업 범위

| 영역 | 작업 내용 |
|---|---|
| 임시저장·복구 | 새로고침 후 복원, 마지막 확정 편집 자동 저장, 저장 중·저장 완료·저장 실패 표시, 손상 데이터 복구 실패 시 기존 작업 보존 |
| 파일·프로젝트 | JSON 저장·열기, 형식 버전·stable ID·데이터 검증, 새 도면·초기화, 작업 교체 시 저장·버리기·취소 |
| 클립보드 | 선택 부품·배선 복사·잘라내기·붙여넣기, 내부 연결 유지, 외부 연결 처리 규칙, 붙여넣기 위치 미리보기·Esc 취소 |
| 프로퍼티즈 | 부품·배선 더블클릭으로 열기, 이름·위치·회전 등 대상에 적합한 속성 편집, 다중 선택의 공통 속성·혼합값 표시 |
| 왼쪽 하이어라키 | 현재 도면의 부품·배선·연결망 탐색 트리, 검색, 도면과 선택 연동, 항목 위치로 화면 이동 |
| 우클릭 메뉴 | 윈도우 스타일 구성, 기능별 그룹·구분선, 아이콘·단축키, 사용할 수 없는 명령 비활성화와 이유 안내 |
| 줌·화면 조작 | 현재 10–200%보다 범위 확대, 커서 중심 줌 유지, 전체·선택 영역 맞춤, 극단 배율의 선택·핀 hit 판정 검증 |
| 그리드·스냅 | 그리드 표시·간격, 스냅 사용·간격, 연결 후보 감지 범위, 가까운 교차점 우선 스냅 옵션 |
| 교차점·연결 표시 | 접속점 강조, 접속·미접속 교차를 모양으로 구분, 후보·확정 대상 강조, 명시적 교차점 접속 |
| 색상 설정 | 배경·그리드·부품·배선·접속점·선택 강조색, 기본값 복원, 색상 이외의 구분 표시 유지 |
| 연결 상태 확인 | 미연결 핀·배선 끝점 목록, 항목 위치로 이동, 선택 연결망 전체 강조 |
| 패널·레이아웃 | 좌우 패널 크기 조절·접기·레이아웃 복원, 하이어라키·도면·프로퍼티즈 선택 동기화 |

## 공통 동작과 검증 기준

- 회로 수정은 기존 Command → Editor 경로를 사용한다. Editor의 상태·명령 책임을 입력 해석 계층으로 옮기지 않는다.
- 회로 편집 작업 하나를 Undo 한 번으로 되돌리고 Redo로 정확히 복원한다. 실패·취소는 회로와 기존 기록을 보존한다.
- 확정 전 미리보기는 회로 저장에서 제외하며 Esc로 취소한다. 텍스트 편집·IME 중에는 도면 명령이 입력을 가로채지 않는다.
- 설정 변경만으로 기존 회로의 위치·경로·전기적 연결을 바꾸지 않는다. 스냅 후보 강조와 실제 연결 확정을 분리한다.
- 입력 프리셋은 물리 입력을 명령에 매핑한다. 프리셋별로 Editor 의미론을 바꾸지 않는다.
- 회로 파일, 브라우저 복구 데이터, 사용자 설정, 화면 상태를 구분한다. 임시저장 성공과 명시적 파일 저장 성공을 구분한다.
- 파일 전체 검증이 성공한 뒤에만 현재 회로를 교체한다. 저장 실패·용량 초과·손상은 안내하고 파일 저장 경로를 제공한다.
- 미구현 명령은 unavailable로 유지한다. 색상만으로 연결 여부나 오류 상태를 구분하지 않는다.
- 단위 테스트로 연결·ID·저장 왕복·Undo 불변식을 확인하고, 브라우저 테스트로 실제 입력·복구·포커스·취소를 확인한다.

## 권장 구현 순서

1. 임시저장·복구와 파일 저장·열기·새 도면
2. 복사·잘라내기·붙여넣기와 프로퍼티즈
3. 하이어라키와 우클릭 메뉴
4. 줌·그리드·스냅·교차점·색상 설정
5. 연결 상태 진단과 패널·레이아웃 마무리

각 단계는 독립적으로 검증하고 커밋한다. 구체적인 줌 범위, 그리드 허용 간격, 속성 항목, 외부 연결 복사 정책은 구현 전 Master Spec과 일치하도록 정의한다.

## 이번 구현에 포함하지 않는 범위

시뮬레이션, 실제 서브회로 계층, 실시간 협업은 후속 범위다. 하이어라키 트리는 현재 도면 탐색 기능이며 서브회로 정의·인스턴스·포트 기능을 뜻하지 않는다.

## Pages와 클라우드 저장 검토안

사용자는 별도 서버 운영 없이 GitHub Pages 기반으로 운영하기를 원한다. Google 등 타사 인증과 사용자 클라우드에 프로젝트를 보관하는 방법은 가능성을 조사한다. 아직 공급자나 구현을 확정하지 않았으며, 계정·클라우드 리소스 생성과 인증 연동은 이 작업 범위 기록 커밋에 포함하지 않는다. 조사 결과는 로컬 편집·저장 기능을 로그인 없이 사용할 수 있는 구조를 기준으로 평가한다.
