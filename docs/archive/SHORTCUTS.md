# Circlith 추천 단축키 세트 v0.1

> **보관 문서 / 구현 기준 아님.** 현재 설계와 구현은 [CIRCLITH_MASTER_SPEC.md](../CIRCLITH_MASTER_SPEC.md)를 우선한다. 아래 내용은 통합 이전의 제안·검토 이력이며, 서로 다른 기본값이나 후보는 현재 명세를 대체하지 않는다.

작성일: 2026-10-13. Windows 데스크톱의 웹 CAD를 기준으로 한 설계 제안이다. 앱 구현과 실제 사용자 검증은 아직 진행하지 않았다.

입력 자료: Circlith CAD Shortcut Benchmark v0 (원본 미포함). 자료에 포함된 제품별 명령은 비교 자료로 취급하며 Circlith의 요구사항으로 자동 채택하지 않는다.

## 선정 기준과 근거의 범위

- 부품 추가·배선·이동·회전·속성처럼 반복하는 작업에는 단일 키를 배정한다.
- CAD의 기존 관습을 참고하되, 초보자의 연결 손실과 웹 브라우저 충돌을 줄이는 쪽을 우선한다.
- Shift는 반대 방향, 추가 상태 또는 빠른 이동처럼 원래 작업의 변형에 사용한다. 모든 조합에 이 규칙이 적용되는 것은 아니다.
- 키의 이름은 기억을 돕는 수단이다. 손 위치만으로 작업 속도가 빠르다고 판단하지 않는다. 오른손 마우스 사용 시 왼손 접근성도 평가하되 실제 효율은 사용성 검사로 확인한다.
- 아래 '관습'은 출처에서 확인한 선례다. '설계 판단'은 Circlith에 맞춘 제안이며 업계 표준이나 측정된 효과를 뜻하지 않는다.
- 첫 버전에 필요한 키와 후속 기능의 키를 분리한다. 기능이 없으면 예약한 키도 가로채지 않는다.

**처음 익힐 세트:** A, W, M, R, E, V, Esc, Backspace, Ctrl+Z, Space+드래그. 나머지는 작업 중 상태줄과 메뉴에서 발견할 수 있도록 한다.

## 1. 첫 버전: 부품·편집

| 키 | 기능과 적용 범위 | 이 키를 추천하는 이유 |
|---|---|---|
| A | 부품 검색창 열기. 검색 후 부품 배치 미리보기 | Add의 첫 글자이고 KiCad·LibrePCB에 선례가 있다 [K][L]. 부품 종류별 키를 외우기 전에 하나의 진입점을 익히게 한다. |
| W | 배선 도구. 연결 가능한 핀/선분 위에서 누르면 그 위치에서 바로 시작 | Wire의 첫 글자이고 KiCad·EasyEDA·LibrePCB에 선례가 있다 [K][E][L]. 빈 공간에서는 배선 대기만 시작해 의도하지 않은 초안을 만들지 않는다. |
| V | 선택 도구로 돌아가기. 진행 초안은 취소하고 기존 선택은 유지 | 기존 Circlith 초안을 유지한다. 시뮬레이션·회로 저장과 연상되는 S를 비워두고, W와 다른 고정 도구를 한 키로 부른다. 회로 CAD 전체의 공통 표준이라는 주장은 하지 않는다. |
| M | 부품/선분 이동 미리보기. 연결 유지가 기본 | Move의 첫 글자라 기억하기 쉽다. 연결 보존 작업을 M과 G 중에서 고르는 부담을 줄인다. KiCad의 M은 연결을 유지하지 않고 G가 유지하므로, Circlith의 M은 의도적으로 의미가 다르다 [K]. |
| R | 선택 대상 또는 배치 초안을 반시계 방향 90° 회전 | Rotate의 첫 글자이며 KiCad·LibrePCB에 선례가 있다 [K][L]. Space를 회전에 쓰지 않아 화면 이동과 구분한다. |
| Shift+R | 시계 방향 90° 회전 | R의 반대 방향을 Shift로 묶고 LibrePCB와 같은 방향 쌍을 사용한다 [L]. 네 번 돌려 원하는 방향을 찾는 조작을 줄이려는 설계다. |
| E | 속성 편집. 단일 대상은 패널 열기, 다중 선택은 공통 속성만 표시 | Edit의 첫 글자이며 KiCad·LibrePCB에 선례가 있다 [K][L]. 더블클릭의 대안으로 제공한다. |
| F2 | 선택한 단일 부품 이름 또는 문자 직접 편집 | Altium의 선택 문자 직접 편집 선례를 이름 편집으로 확장한다 [A]. E는 전체 속성, F2는 이름/내용 하나로 역할을 구분한다. 이름 필드가 없으면 실행하지 않는다. |
| Shift+D | 선택 대상 복제 후 커서에 붙여 배치 미리보기 | Duplicate의 D를 유지하되 Chrome의 북마크 Ctrl+D를 피한다 [C]. 회로 CAD 공통 관습은 아니며, 선택이 없으면 아무것도 복제하지 않는다. |
| Delete | 선택한 대상 삭제 | 벤치마크 CAD들이 공통으로 사용하는 삭제 키다. 커서 아래 대상을 직접 지우지 않아 오삭제를 줄인다. |
| 방향키 | 선택 대상을 그리드 1칸 이동 | 방향 자체로 결과를 예상할 수 있다. Altium의 커서 이동 대신 선택 대상을 직접 움직이는 Circlith 설계다. 연결을 유지하며, 선택이 없으면 아무것도 이동하지 않는다. |
| Shift+방향키 | 선택 대상을 그리드 10칸 이동 | 작은 이동과 큰 이동을 같은 방향키에 묶는다. 10칸은 Altium의 이동 증분 선례를 참고했다 [A]. 실제 선호 증분은 검증한다. |

방향키 반복 입력은 한 번 누르고 놓는 동안 하나의 이동 작업으로 묶는다. 텍스트 입력 중에는 커서 이동, 배치 초안 중에는 초안 이동으로 처리하며 확정 회로를 따로 움직이지 않는다.

## 2. 첫 버전: 배선·취소

| 키 | 기능과 적용 범위 | 이 키를 추천하는 이유 |
|---|---|---|
| Shift+Space | 배선 초안의 가로 우선/세로 우선 꺾임 전환 | 왼손으로 누르기 쉬운 조합을 후보로 삼는다. Tab을 포커스 이동으로 남기고, Space 단독+드래그의 화면 이동과 수정키로 구분한다. Circlith의 자체 배정이며 Altium의 같은 키가 동일 기능이라는 뜻은 아니다. |
| Backspace | 배선 중 마지막 경유점 제거. 경유점이 없으면 초안 취소 | 방금 입력한 내용을 뒤로 되돌리는 의미와 일치하고 Altium 배선에도 선례가 있다 [A]. Delete까지 같은 역할로 쓰면 확정 객체 삭제와 혼동하므로 초안에서는 Delete를 소비하되 삭제 명령은 실행하지 않는다. |
| Enter | 배치·붙여넣기·키보드 이동 미리보기 확정. 배선 중에는 강조된 유효 대상에 연결 | 클릭 확정의 키보드 대안이며 Altium의 Enter=클릭 선례를 참고한다 [A]. 유효한 연결 대상이 없으면 Enter로 미연결 배선을 만들지 않는다. |
| Esc | 진행 작업 하나 취소 → 배선 대기 종료 → 선택 해제 | 여러 CAD가 취소에 사용하는 키다. 먼저 가장 가까운 작업을 취소해 회로 전체에 영향을 주지 않는다. 실행 중 시뮬레이션 정지와 혼용하지 않는다. |
| Alt 유지 | 배치·이동·배선에서 그리드 스냅만 임시 해제 | 설정을 켜고 끄는 두 번의 조작 없이 정밀 배치할 수 있다. Ctrl의 선택·클립보드 역할과 Shift의 연속 배치 역할을 비켜간다. 핀/접속점 스냅과 연결 확정은 유지한다. |
| Shift+클릭 | 배치 중: 연속 배치. 선택 도구에서는 선택 상태 토글 | 원래 조작의 확장으로 이해할 수 있다. 선택 토글은 Altium 선례가 있다 [A]. 도구 상태가 명확할 때만 의미가 바뀌며 배선 진행에서는 연속 부품 배치로 처리하지 않는다. |
| Tab / Shift+Tab | 화면 버튼·패널·입력 필드의 다음/이전 포커스로 이동 | 브라우저 기본 탐색을 유지한다 [C]. 이전 Circlith 초안의 Tab=배선 꺾임 전환을 변경한다. 입력 필드에 포커스가 가면 도면 단축키는 멈춘다. |

Shift+Space는 도면에 포커스가 있고 배선 초안이 있을 때만 가로챈다. 이를 누른 이벤트는 Space 화면 이동을 시작하지 않는다. 일반 Space+드래그로 화면을 이동하는 동안에는 배선 초안을 잠시 유지하고 편집 클릭을 소비하지 않는다.

Tab으로 포커스가 이동하는 것은 의도적인 UI 탐색이다. 초안은 잠시 유지하고 Esc/도면 재포커스로 돌아갈 수 있게 한다. 창이 비활성화되거나 포인터 캡처를 잃으면 기존 명세대로 제스처를 롤백한다.

## 3. 첫 버전: 선택·공통 편집·파일

| 키 | 기능과 적용 범위 | 이 키를 추천하는 이유 |
|---|---|---|
| Ctrl+A | 도면의 모든 편집 대상 선택 | 여러 CAD와 텍스트 편집의 익숙한 전체 선택 규칙을 유지한다. 입력 필드에서는 텍스트만 선택한다. |
| Ctrl+C | 선택 복사 | CAD와 일반 편집의 관습을 유지해 새로 학습할 필요를 줄인다. 선택 부품 사이의 내부 배선도 포함한다. |
| Ctrl+X | 선택 잘라내기 | 복사·붙여넣기와 같은 편집 묶음을 유지한다. 클립보드 기록에 성공한 뒤 삭제하며 한 번의 Undo로 복구한다. |
| Ctrl+V | 붙여넣기 미리보기 | 기존 관습을 유지하되 클릭/Enter로 확정하기 전 위치를 확인하게 한다. 실패하면 원본 회로를 변경하지 않는다. |
| Ctrl+Z | Undo | 여러 CAD와 일반 편집의 관습을 유지한다. 배선 완료·이동·복제 등 사용자 작업 하나를 되돌린다. |
| Ctrl+Shift+Z | Redo 기본 키 | Undo와 같은 Z에 Shift를 더해 반대 방향을 표시한다. LibrePCB도 대안 키로 제공한다 [L]. |
| Ctrl+Y | Redo 별칭 | KiCad·Altium·LibrePCB와 Windows 사용자의 기존 습관을 수용한다 [K][A][L]. 두 키는 같은 명령을 호출한다. |
| Ctrl+S | 현재 회로를 파일로 저장 | 익숙한 저장 키를 유지한다. 웹페이지 HTML 저장과 구분해 앱 포커스에서만 처리하고, 파일 저장 완료 여부와 자동 복구 상태를 따로 표시한다. |
| Ctrl+O | 회로 파일 열기 | 익숙한 열기 키를 유지한다. 읽기·검증 성공 전에는 현재 회로를 교체하지 않는다. 앱 포커스에서만 처리한다. |
| Ctrl+F | 회로 대상 검색: 부품 이름·신호 이름 | Find의 관습을 유지한다. 도면에서 검색이 필요한 대상에 집중하며, 부품 라이브러리 추가는 A로 구분한다. 앱 포커스가 없으면 브라우저 검색을 유지한다. |
| ? | 현재 상태의 단축키 안내 | 질문/도움의 의미가 직접적이며 F1의 Chrome 도움말과 구분한다 [C]. 미국식 배열의 Shift+/ 등 '?'를 입력하는 조합으로 호출한다. 다른 배열에서는 화면 도움말 버튼도 제공한다. |

Ctrl+S/O/F는 브라우저와 겹치는 익숙한 명령을 앱에서 의도적으로 처리하는 예외다. 특정 브라우저나 내장 브라우저에서 이벤트를 받지 못하면 화면 버튼을 사용한다. 원래 브라우저 명령이 어디서나 차단된다고 보장하지 않는다.

Ctrl+N, Ctrl+Shift+S, Ctrl+Shift+A는 초기 기본 세트에 넣지 않는다. 각각 브라우저 새 창/제품별 별도 기능과의 혼동 또는 Esc와의 기능 중복을 줄인다. 새 도면과 내보내기는 메뉴에서 접근한다.

## 4. 첫 버전: 화면·그리드

| 키/입력 | 기능과 적용 범위 | 이 입력을 추천하는 이유 |
|---|---|---|
| Space+왼쪽 드래그 | 임시 화면 이동 | 중간 버튼이 없는 트랙패드에서도 도구 전환 없이 이동할 수 있다. Space만 누르면 회전·입력 전환·실행을 하지 않는다. |
| 휠 버튼 드래그 | 화면 이동 | KiCad·LibrePCB의 중간 버튼 화면 이동 선례를 수용한다 [K][L]. Space 경로와 함께 제공해 장치 선택을 강제하지 않는다. |
| 마우스 휠 | 커서 중심 확대/축소 | KiCad·LibrePCB의 선례를 참고한다 [K][L]. 보고 있는 위치를 유지하므로 확대 후 다시 화면을 찾는 작업을 줄이려는 설계다. |
| + / - | 화면 중심 확대/축소 | 기호가 크기 변경을 설명하고 휠 없는 사용자의 대안이 된다. Ctrl을 붙이지 않아 브라우저 페이지 확대와 구분한다. 메인 키보드 '+' 입력 및 숫자패드의 +/-를 지원한다. |
| Home | 회로 전체 보기 맞춤 | 회로에서 길을 잃었을 때 한 키로 복귀한다. 기존 Circlith 초안을 유지한다. 입력 필드의 Home 동작은 유지한다. |
| Shift+Home | 선택 대상 보기 맞춤 | Home과 같은 보기 맞춤 묶음이다. 선택이 없으면 동작하지 않아 갑작스러운 전체 화면 변경을 피한다. |
| G | 그리드 표시 토글 | Grid의 첫 글자로 기억하기 쉽다. M이 연결 유지 이동을 담당하므로 G를 별도 Drag 명령으로 쓰지 않는다. 표시만 바뀌고 스냅 설정은 유지한다. |

우클릭은 기본적으로 컨텍스트 메뉴에 사용한다. 우클릭을 이전 도구 복귀·취소·화면 이동까지 맡기지 않아 결과를 예측하기 쉽게 한다. Esc가 취소의 공통 경로다. 커서가 도면 밖이면 휠과 Home 등은 해당 UI의 기본 동작을 유지한다.

## 5. 후속 기능용 예약 키

해당 기능을 만들 때 활성화한다. 아래 배정 자체가 기능 제작 범위를 늘리지 않는다.

| 키 | 기능 | 이 키를 추천하는 이유 |
|---|---|---|
| N | Net Label 배치 | Net의 첫 글자이며 EasyEDA·LibrePCB 선례가 있다 [E][L]. L과 N을 동시에 별칭으로 쓰지 않아 그래픽 선과의 혼동을 줄인다. |
| T | 설명 문자 배치 | Text의 첫 글자이며 EasyEDA·LibrePCB 선례가 있다 [E][L]. 전기적 이름인 N과 역할을 분리한다. |
| H | 대상 네트 강조/해제 | Highlight의 첫 글자이며 EasyEDA 선례가 있다 [E]. 선택 부품을 편집하는 작업과 연결망 추적을 구분한다. |
| Shift+H | 모든 네트 강조 해제 | H 기능을 전체에 적용하는 변형이며 EasyEDA에 선례가 있다 [E]. Esc의 초안/선택 취소 의미를 흐리지 않는다. |
| P | 신호 Probe 배치 | Probe의 첫 글자. 논리 시뮬레이션에서 필요한 관측 작업에 단일 키를 준다. 다른 CAD의 P=Pin/Place와 다르며 심벌 핀 제작용 키로 동시에 쓰지 않는다. |
| X | 좌우 대칭: x좌표 반전 | KiCad의 축별 대칭 키를 참고한다 [K]. 축 이름만 쓰면 혼동할 수 있어 메뉴와 미리보기에 '좌우 대칭'을 표시한다. |
| Y | 상하 대칭: y좌표 반전 | X와 한 쌍이며 명확한 수평/수직 피드백을 제공한다 [K]. 핀과 연결도 함께 변환한다. |
| Ctrl+Enter | 시뮬레이션 실행/일시 정지 | 확정의 Enter에 Ctrl을 더해 시간 진행 제어로 분리한다. F5 새로고침, F6 포커스 이동, F7 캐럿 탐색을 피하려는 자체 설계다 [C]. 도면에 포커스가 있고 편집 초안이 없을 때만 실행한다. |
| Shift+Enter | 다음 이벤트 한 단계 진행 | Enter 계열에 시간 제어를 묶되 수정키로 연속 실행과 구분한다. 일시 정지 상태에서만 실행하고 실행 중에는 안내한다. |
| Ctrl+Shift+Enter | 시뮬레이션 Reset: t=0, 상태·파형 초기화 | 실행 키에 수정키를 추가해 이력을 지우는 작업을 구분한다. 자동 반복은 무시하며 편집 초안/입력 필드에서는 실행하지 않는다. |

예약한 시뮬레이션 키는 주소창에서 의미가 다를 수 있다 [C]. 도면 포커스 확인이 전제이며 OS/브라우저가 키 이벤트를 제공하지 않으면 가로챌 수 없다. 첫 조합회로 버전에서는 입력 변화마다 재계산하므로 시간 제어 키는 필요 없다.

B는 향후 Bus용으로 남기고 현재 동작을 주지 않는다. I/O는 특정 입력·출력 부품 배치용 후보로만 남긴다. 게이트·클록·포트마다 별도 키를 늘리기 전에 A 검색과 최근 부품으로 충분한지 검증한다. 정렬·간격 조정과 선택 세트는 빈도가 확인되기 전에는 메뉴를 사용한다.

## 6. 키보다 먼저 확정할 대상 선택 규칙

1. R은 활성 배치/붙여넣기 초안 → 명시적 선택 → 커서 아래 단일 대상 순으로 적용한다.
2. M/E는 진행 초안이 없을 때 명시적 선택을 우선한다. 선택이 없으면 커서 아래 대상을 강조하고 동작한다. E는 부품 배치 초안의 속성 편집도 허용한다.
3. W는 선택과 무관하게 커서 아래 연결 가능한 핀/접속점/선분을 우선한다. 배선 진행 중 다시 W를 누르면 현재 초안을 유지한다.
4. 선택 그룹이 있는데 커서가 다른 부품 위에 있어도 M/R/E는 선택 그룹에 적용한다. 상태줄에 대상 수를 표시한다.
5. 후보가 중첩되면 이름·미리보기로 대상을 명확히 하고 선택 팝업을 제공한다. 모호한 상태에서 회로를 바로 변경하지 않는다.
6. Delete, 잘라내기, 복제는 명시적 선택에만 적용한다. Hover만으로 파괴적 명령을 실행하지 않는다.
7. 초안 중 새 도구 A/V를 누르면 초안을 폐기하고 요청한 도구로 전환한다. 호환되지 않는 M/F2/복제/시뮬레이션 명령은 실행하지 않고 안내한다.

KiCad의 '선택이 없으면 커서 아래 대상' 방식을 일부 적용한 설계다 [K]. 삭제까지 커서 우선으로 확대하지 않으며, 명령 전에 강조한 대상과 실제 적용 대상이 같아야 한다.

## 7. 웹·한글 입력·키 설정 정책

- 입력·검색·textarea·contenteditable·모달이 활성화되면 도면 단일 키와 편집 명령을 처리하지 않는다. Ctrl+A/C/X/V/Z와 방향키는 입력 UI에 맡긴다.
- 도면은 클릭/키보드 탐색으로 명시적으로 포커스를 얻는다. 마우스가 도면 위에 있다는 이유만으로 다른 입력 필드의 포커스를 빼앗지 않는다.
- 한글 IME 조합 중(isComposing), 조합 시작/끝 경계에서는 도면 명령을 실행하지 않는다 [M]. 단일 영문 명령은 편집기 포커스에서 물리 키 위치를 기준으로 해 한/영 상태와 무관하게 유지하는 안을 먼저 검증한다. 다른 키보드 배열에서는 설정 UI에 실제 키를 표시하고 재배정을 허용한다.
- '+'와 '?' 같은 기호는 입력 문자와 숫자패드 키를 별도로 처리한다. Ctrl/Alt/Shift/Meta 조합은 정확히 구분하고, Shift+D가 D나 Ctrl+D로 잘못 처리되지 않게 한다.
- 매핑된 유효 명령을 처리한 경우에만 preventDefault를 적용한다. 잘못된 도구/초안 상태에서의 위험한 편집 키는 안내와 함께 소비한다. Tab은 기본 이동을 유지한다.
- 배치·회전·삭제·실행 토글 등의 keydown 자동 반복은 무시한다. 방향키의 반복 이동만 허용하고 keyup/포커스 상실에서 작업을 마감한다.
- 단축키는 재배정·초기화 가능하게 설계한다. 같은 상태에서 중복 배정하면 저장 전에 충돌을 표시한다. 브라우저 예약키는 경고하며 대체 버튼을 유지한다.
- 문자 하나로 동작하는 명령을 끌 수 있는 설정을 제공한다. 스크린리더·음성 입력과 다른 배열 사용을 함께 검증한다.
- macOS의 Cmd/Option 변환은 별도 프로필에서 검증한다. Windows Ctrl/Alt를 기계적으로 치환해 지원 완료로 주장하지 않는다.

## 8. 기존 Circlith 초안에서 변경하는 내용

| 항목 | 이전 초안 | 추천안 | 이유 |
|---|---|---|---|
| 부품 추가 | 목록/검색 클릭 | A로 검색 진입 추가 | 자주 반복하는 작업의 키보드 경로 확보 |
| 이동 | 드래그 | M과 드래그 모두 연결 유지 | 키보드 진입과 마우스 조작의 결과 일치 |
| 배선 꺾임 | Tab | Shift+Space | 포커스 이동 보존 |
| 회전 방향 | R=90°, 방향 미정 | R=반시계, Shift+R=시계 | 구현마다 방향이 바뀌지 않도록 명세 |
| 대상 규칙 | 주로 선택 | 선택 우선, 비선택일 때 Hover 보조 | 반복 선택을 줄이되 삭제 안전성 유지 |
| 시뮬레이션 | 키 미정 | Ctrl+Enter 계열 예약 | F5와 브라우저 탐색 기능의 충돌 회피 |

## 9. 검증해야 할 항목

- A→검색→배치→R→W→Shift+Space→연결→M→Esc 흐름을 마우스 메뉴 개입 없이 검사한다.
- M의 연결 보존 의미를 KiCad 사용자가 잘 이해하는지 확인한다. 필요하면 별도의 KiCad 호환 프로필을 검토하되 기본 의미를 섞지 않는다.
- Shift+Space를 누를 때 도면이 이동하거나 페이지가 스크롤되지 않아야 한다. 일반 Tab은 패널로 이동해야 한다.
- 한/영 상태, IME 조합, 입력 필드의 Backspace/Delete/Space/R과 자동 반복을 검사한다.
- Chrome·Edge·내장 브라우저에서 파일 열기/저장/복사 키가 지원되는지 실제 확인한다. 아직 검사 완료가 아니다.
- 새로운 키 세트와 기존 초안으로 같은 회로를 만드는 시간을 비교하고 오명령·도구 전환·도움 요청을 기록한다.

## 출처와 비교상의 주의

- [K] [KiCad 9 Schematic Editor](https://docs.kicad.org/9.0/en/eeschema/eeschema.html): 선택/Hover 대상, M/G 연결 정책, 회전·속성·배선과 뷰 조작. KiCad의 M/G를 같은 기능으로 요약하면 안 된다.
- [E] [EasyEDA Pro Shortcut Key](https://prodocs.easyeda.com/en/introduction/hotkeys/): W/N/T/H와 핀·네트 라벨 배치 중 Tab 설정. 도형 R=Rectangle과 공통 Space=Rotate가 있어 R=Rotate라는 공통 결론의 근거로 사용하지 않았다.
- [L] [LibrePCB 0.1.7 Shortcut Reference](https://librepcb.org/blog/2022-10-03_release_0.1.7/keyboard_shortcuts_reference.pdf): A/W/E, R/Shift+R, 기본 편집·뷰. 2022년 0.1.7 자료이며 최신 버전의 모든 기본값을 보증하지 않는다.
- [A] [Altium Schematic Editor Shortcuts](https://www.altium.com/documentation/altium-designer/shortcut-keys/schematic-editors): F2, 선택 토글, 증분 이동, Backspace, Enter. Prefix 메뉴와 PCB 전용 작업은 기본 세트로 이식하지 않았다.
- [C] [Chrome keyboard shortcuts](https://support.google.com/chrome/answer/157179?hl=en): Ctrl+D 북마크, F5 새로고침, F6 탐색, F7 캐럿 탐색, 포커스 및 파일 명령의 충돌 참고. 다른 브라우저는 별도 검사 대상이다.
- [M] [KeyboardEvent.isComposing](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/isComposing): IME 조합 여부 판별. 입력 경계 처리의 구체적 동작은 실제 브라우저에서 검증한다.

첨부 벤치마크의 '강하게 수렴하는 키'는 디자인 후보를 찾는 데 활용했다. 제품·버전·회로도/PCB 맥락이 서로 다르므로 모든 키를 업계 공통 표준으로 표현하지 않는다. 특히 OrCAD X Presto의 PCB 키를 논리회로 CAD 기본키의 직접 근거로 사용하지 않았다.
