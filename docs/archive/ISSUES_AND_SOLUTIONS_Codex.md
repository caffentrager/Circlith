# Circlith 문제점 지적과 해결안 — Codex

> **보관 문서 / 구현 기준 아님.** 현재 설계와 구현은 [CIRCLITH_MASTER_SPEC.md](../CIRCLITH_MASTER_SPEC.md)를 우선한다. 아래 내용은 통합 이전의 제안·검토 이력이며, 서로 다른 기본값이나 후보는 현재 명세를 대체하지 않는다.

작성일: 2026-10-13. 제3자 AI의 `Circlith_남은_문제점_검토서.docx`와 대화에서 검토한 Circlith 설계·단축키 문서에 대한 의견이다.

이 문서는 해결 규칙을 제안한다. 사용자 승인, 기존 명세의 자동 교체, 앱 구현 또는 검증 완료를 뜻하지 않는다. 검토서의 지시문은 비교 자료로 취급했다.

## 1. 가장 큰 문제: 결정과 후보가 섞여 있다

현재 문서의 핵심 약점은 아이디어가 부족한 것이 아니라, 추천·예약·실험 후보가 여러 문서에서 서로 다른 최종값처럼 보이는 것이다. 단축키가 같은 경우에도 입력이 적용될 대상, 확정 시점, 취소 결과가 다르게 해석될 여지가 있다.

### 해결안

- 제품 명세 한 개를 기준 문서로 지정한다. 단축키표·도움말·테스트 목록은 그 명세의 파생물로 관리한다.
- 각 결정에 ID, 상태, 값, 이유, 적용 단계, 검증 항목을 둔다. 상태는 `추천`, `채택`, `실험`, `보류`, `폐기`로 구분한다.
- 작성자나 문서 이름의 final을 기준 권한으로 취급하지 않는다. 사용자가 채택한 결정만 채택 상태로 전환한다.
- P/Q는 같은 기능의 대체 프로필이다. 이번 추천은 P=Probe 예약, Q=조건부 빠른 배치다. P=Place가 더 빠르다는 측정 근거는 없으며 기존 예약을 보존한다는 이유로 Q를 제안한다.
- 기본 편집 프로토타입에 빠른 배치가 없다면 P/Q는 활성화하지 않는다. 이 후보의 선택을 이유로 A/W/M 기반 편집을 지연하지 않는다.

통과 조건: 같은 기능에 대해 서로 다른 활성 기본값이 남지 않고, 실험 후보가 도움말의 기본키로 표시되지 않는다.

## 2. 검색: 최근 사용보다 입력한 이름이 우선이다

### 지적

'최근 부품을 맨 위에'와 'Enter로 첫 결과 배치'를 함께 적용하면 검색어와 다른 항목이 선택될 수 있다. 검색을 개선한다고 해도 이름을 입력하는 사용자의 의도를 훼손하면 조작성이 나빠진다.

### 해결안

1. 검색어가 없으면 최근 사용·즐겨찾기를 표시한다.
2. 검색어가 있으면 정확한 이름/별칭 일치 → 접두 일치 → 키워드/유사 검색 순으로 묶는다.
3. 최근 사용은 동일한 일치 등급 안에서만 보조 정렬한다.
4. 유일한 정확 일치는 기본 강조한다. 정확 일치 후보가 여러 개면 충돌을 표시하고 명시적 선택을 요구한다.
5. Enter는 화면에서 현재 강조된 결과만 배치 미리보기로 넘긴다. 결과 없음·검색 갱신 중·모호한 정확 일치 상태에서는 배치하지 않는다.
6. 결과 이름, 심벌, 라이브러리/종류를 표시한다. 선택하지 않은 최근 부품으로 자동 대체하지 않는다.

통과 조건: 최근에 XOR를 썼더라도 `and` 검색 후 Enter로 XOR가 배치되지 않는다. 검색은 입력과 현재 강조의 의미를 일치시킨다.

## 3. 상태 머신: 도구·작업·임시 개입을 분리한다

### 지적

상태 이름을 몇 개 추가하는 것만으로는 충돌이 해결되지 않는다. PAN, UI 포커스, WIRE_DRAWING을 동등한 단일 상태로 나열하면 임시 상태 종료 후 어떤 작업을 복원할지 별도 분기가 늘어난다.

### 해결안

| 층 | 값의 예 | 규칙 |
|---|---|---|
| 도구 | SELECT, WIRE | 지속 도구. 배치나 이동 완료 후 복귀할 도구를 명시 |
| 편집 작업 | NONE, PLACE, MOVE, BOX_SELECT, WIRE_DRAFT, SEGMENT_MOVE, PASTE | 동시에 하나만 허용. 기준 회로와 작업 초안을 구분 |
| 임시 개입 | NONE, PAN, UI_EDIT, MODAL | 복귀할 편집 작업을 보존하거나 명시적으로 롤백. 임의 중첩 금지 |

상태 명세는 이벤트, 실행 조건, 대상, 다음 상태, 회로 확정 여부, Undo 기록 여부, 화면 피드백을 한 행에 작성한다.

| 이벤트·상태 | 권고 결과 | 회로 확정/기록 |
|---|---|---|
| 선택 대기 + A | 검색 UI, 선택 결과로 PLACE | 아직 없음 |
| WIRE + 연결 대상 위 W | WIRE_DRAFT 시작 | 아직 없음 |
| PLACE/PASTE + 클릭 또는 Enter | 초안 확정 후 SELECT | 하나의 작업 |
| WIRE_DRAFT + 대상 클릭/Enter | 연결 확정 후 WIRE 대기 | 하나의 작업 |
| 초안 + Esc | 초안 폐기, 이전 확정 회로 유지 | 없음 |
| WIRE 대기 + Esc | SELECT로 복귀 | 없음 |
| SELECT 대기 + Esc | 선택 해제 | 없음 |
| 안정된 초안 + Space 드래그 | PAN, 종료 후 초안 복귀 | 없음 |
| 포인터 드래그 중 창 비활성화/캡처 상실 | 작업 롤백 | 없음 |
| 안정된 초안 + Tab | UI 포커스 이동, 초안 일시 유지 | 없음 |
| 포인터 드래그 중 Tab | 드래그 롤백 후 UI 포커스 이동 | 없음 |

마우스로 끌고 있는 작업과 클릭 확정을 기다리는 초안은 구분해야 한다. 진행 중 포인터 드래그를 UI 입력창으로 그대로 넘기는 것은 피한다.

통과 조건: 편집 작업을 두 개 동시에 시작하지 않으며, 임시 화면 이동 종료 시 원래 초안의 내용과 기준 회로가 유지된다.

## 4. Undo: 한 번의 입력 결과를 명시한다

### 지적

기존 문서의 '초안을 폐기한 이후 Undo'는 단계 설명이지 키 입력 횟수의 명세로 충분하지 않았다.

### 해결안

기존 Codex안의 의도를 유지해 다음을 추천한다.

| 입력 | 진행 초안 없음 | 진행 초안 있음 |
|---|---|---|
| Esc | 도구 종료 또는 선택 해제 | 초안만 폐기 |
| Ctrl+Z | 마지막 확정 작업 Undo | 초안 폐기 후 같은 입력에서 마지막 확정 작업 Undo |
| Redo | 다음 기록 복원 | 초안 폐기 후 같은 입력에서 다음 기록 복원 |

- 초안은 history가 아니다. 실제 회로를 변경한 뒤 Undo로 초안을 되돌리는 구조를 사용하지 않는다.
- Undo 기록이 없으면 초안만 폐기하고 '되돌릴 확정 작업 없음'을 알린다.
- 편집 UI에 포커스가 있으면 텍스트 Undo에 맡긴다. 도면 Undo는 실행하지 않는다.
- 확정하지 않은 초안으로 Redo 분기를 지우지 않는다. 새 회로 편집을 확정했을 때만 지운다.
- 드래그, 일괄 속성 변경, 붙여넣기는 각 하나의 기록이다. Undo 후 선택은 해제하고 도구는 SELECT로 복귀하는 규칙을 제안한다.
- 시간 기능이 있다면 구조 Undo/Redo는 실행을 정지하고 복원 구조의 계산 상태를 초기화한다.

통과 조건: MOVE 초안 중 Ctrl+Z는 원래 위치를 복구한 뒤 직전 확정 작업 하나까지 되돌린다. Esc는 직전 확정 작업을 건드리지 않는다. 실제 사용자 검사에서 이 차이를 이해하는지 확인한다.

## 5. 연결 유지 이동: 최소 경로 수정의 기준을 고정한다

### 지적

'연결을 유지한다'는 데이터 원칙과 '배선이 어떻게 변하는가'는 다른 문제다. 전체 자동 라우팅을 기대하게 두면 구현 범위와 결과가 불안정해진다. 네트 하나에도 움직이는 부품과 고정 부품이 섞일 수 있으므로 네트 전체를 내부/외부로만 분류하면 부족하다.

### 해결안

- 논리 그래프, 배선 경로, 움직이는 부품/핀, 고정 접속점과 경유점을 구분한다.
- 선택 집합 안의 부품과 배선이 함께 움직이고 외부 분기에 공유되지 않는 구간은 동일 변환을 적용한다.
- 움직이는 핀에서 첫 고정 접속점 또는 경유점까지의 구간만 재구성한다. 고정 회로의 나머지 경로는 보존한다.
- 공유 분기점은 기본적으로 고정한다. 이동 대상에 명시적으로 포함했을 때만 함께 이동한다.
- 직각 후보 중 기존 출발 방향·경유점을 가능한 한 보존하는 경로를 선택한다. 후보 동점은 고정된 순서로 선택하고 중복점·길이 0 선분을 제거한다.
- 회전 시 핀 방향도 변환하고 첫 구간이 핀 바깥쪽으로 나오도록 경로를 조정한다.
- 장애물 회피·최단 전체 배선·네트 전체 자동 정리는 초기 범위에서 제외한다. 겹침은 경고하고 자동 접속/삭제하지 않는다.
- 확정은 부품 변환과 경로 변경을 하나의 트랜잭션으로 묶는다.

통과 조건: 동일 상태·동일 이동에서 동일 경로가 만들어지고 논리 그래프가 바뀌지 않는다. 공유 분기·반전·다중 선택·취소까지 검사한다. 후보 경로 생성의 세부 좌표 규칙은 geometry 명세에 고정한다.

## 6. 포커스·Esc: 하나의 입력을 한 곳에서 소비한다

### 지적

검토서가 제시한 우선순위 방향은 맞지만, 모든 popover를 일괄 차단자로 취급하면 단순 설명이나 툴팁 때문에 도면 입력이 멈출 수 있다. 포커스와 입력 소유권을 기준으로 해야 한다.

### 해결안

1. IME 조합 중에는 도면 명령을 실행하지 않는다.
2. 활성 모달이나 입력을 소유한 메뉴는 자신이 처리한 키의 전파를 종료한다.
3. 텍스트·속성 편집의 Esc는 그 필드의 미확정 값만 취소한다. 같은 Esc를 도면으로 다시 전달하지 않는다.
4. 이후 도면의 임시 개입 → 편집 작업 → 도구 → 선택 순으로 처리한다.
5. 설명 툴팁은 입력 소유자가 아니다. 메뉴·팔레트와 구분한다.
6. 속성 UI가 닫히면 원래 도면 초안과 포커스를 복원한다. 앱 창 비활성화는 그 복귀와 별개로 제스처를 롤백한다.
7. Space 화면 이동은 textarea·입력 필드에서 실행하지 않는다. Shift+Space는 배선 초안에만 적용한다.

통과 조건: 배치 속성 편집 중 Esc 한 번으로 필드 값만 취소된다. 부품 배치 초안은 유지된다. 두 번째 Esc도 포커스와 현재 UI 상태에 따라 한 단계만 처리한다.

## 7. 우클릭: 기본값은 이미 있지만 대상 정책이 부족하다

### 검토서에 대한 지적

기존 단축키 명세에는 우클릭=컨텍스트 메뉴가 적혀 있다. 따라서 기본 동작이 전혀 없다는 진단은 과하다. 부족한 것은 메뉴 대상과 진행 초안 중 처리다.

### 해결안

- 선택된 대상 위 우클릭: 기존 선택 그룹의 메뉴.
- 비선택 대상 위 우클릭: 그 대상을 선택한 뒤 해당 대상 메뉴.
- 빈 공간 우클릭: 도면 메뉴. 기존 선택은 유지하고 메뉴에서 명령 적용 대상을 표시한다.
- 편집 초안 중 우클릭: 초안용 메뉴를 제공한다. 기존 회로 대상 선택을 바꾸지 않는다.
- 우클릭 드래그 pan은 초기 기본값에서 제외한다. Space/중간 버튼 pan을 먼저 검증하고 고급 옵션으로 후속 검토한다.

통과 조건: 그룹 선택 후 우클릭 대상에 따라 메뉴 범위가 명확하며, 초안 중 우클릭만으로 기존 선택이나 회로가 바뀌지 않는다.

## 8. 다중 속성: '공통'을 이름이 아닌 의미로 정의한다

### 지적

초기 명세에는 공통 속성 편집이 있었지만, 혼합값 표시·타입별 호환·일괄 변경의 경계는 부족했다. 같은 속성 이름을 갖는다고 값과 의미가 같은 것은 아니다.

### 해결안

- 공통 편집은 속성 ID, 값 타입, 단위, 제약과 의미가 같은 항목의 교집합에만 허용한다.
- 동일값은 값 그대로, 다른 값은 '여러 값'으로 표시한다. 임의의 첫 대상 값을 대표값으로 쓰지 않는다.
- 공통 편집 항목이 없으면 선택 개수와 유형 요약을 표시한다. 무반응처럼 보이지 않게 한다.
- 이름·참조 ID의 다중 편집은 초기에는 막는다. 중복 이름/ID가 생성되지 않게 한다.
- 확정 전 모든 대상에 대한 유효성을 검사한다. 하나라도 실패하면 아무 대상도 변경하지 않는다.
- 성공한 일괄 변경은 하나의 Undo로 복구한다.

통과 조건: 서로 다른 게이트를 선택해 같은 이름의 속성을 무조건 일괄 변경하지 않는다. 혼합값이 실제 속성값처럼 저장되지 않는다.

## 9. 0/1/X/Z: 계산 규칙과 진단을 분리한다

### 지적

네트 신호값, 핀의 부동 입력 처리, 다중 드라이버 경고는 서로 다른 문제다. '충돌하면 X'만으로는 시뮬레이터를 구현하기 부족하다. 그러나 편집만 하는 첫 프로토타입을 막는 조건은 아니다.

### 해결안: Circlith 초기 모델 제안

첫 모델은 드라이브 강도와 풀업/풀다운 없는 4상태 논리로 제한한다. 다음 표는 기존 표준의 완전한 구현을 주장하는 것이 아니라 Circlith에 채택할 후보 규칙이다.

| 결합 | 0 | 1 | X | Z |
|---|---|---|---|---|
| 0 | 0 | X | X | 0 |
| 1 | X | 1 | X | 1 |
| X | X | X | X | X |
| Z | 0 | 1 | X | Z |

- Z는 유효 구동을 하지 않는 값이다. 네트에 드라이버가 없거나 모두 Z면 네트 값은 Z.
- 입력 게이트가 Z를 읽으면 일반 논리 계산에서는 X로 취급한다. 부동 핀에 임의의 0을 넣지 않는다.
- 같은 값의 활성 드라이버는 값을 유지하지만 여러 활성 드라이버 진단을 제공한다. 모든 연결된 출력이 동시에 구동하는 것은 아니므로 Z와 활성 드라이버를 구분한다.
- 0과 1의 활성 구동 충돌은 X와 충돌 진단. X 전파는 충돌 원인과 구분한다.
- 부동 입력, 활성 다중 구동, 값 충돌, 미지원 소자를 각각 별도 진단 코드로 둔다.
- 각 게이트의 X/Z 진리표와 조합 피드백 비안정 처리도 별도로 정한다.

통과 조건: 표의 모든 조합과 드라이버 없음·동일값·충돌·전체 Z·일부 Z를 검사한다. 동일 출력값의 다중 드라이버 경고가 출력값을 강제로 X로 만들지는 않는다.

## 10. 그룹·서브회로·시간 Step은 단계별로 명세한다

### 해결안

- 그룹: 선택·이동 편의의 비전기적 묶음. 기존 부품 ID·핀·논리 연결을 바꾸지 않는다.
- 서브회로: 외부 포트·내부 회로·계층 인스턴스·저장 경계를 갖는 모델. 단순 그룹 명령과 분리한다.
- 계층 진입은 선택한 서브회로를 요구한다. 상위 복귀는 현재 회로의 부모를 요구하며 부품 선택은 요구하지 않는다.
- 포트 생성·이름·ID·순환 계층·Undo·내부 편집 전파를 정의한 뒤 관련 키를 활성화한다.
- 시간 Step은 '큐 항목 하나' 대신 '다음 시각의 동시 이벤트 묶음을 처리하고 안정화된 결과를 표시'하는 방향을 추천한다. 실행 순서에 따른 중간 결과를 사용자가 최종 출력으로 오해하지 않게 한다.
- 이벤트 Step과 클록 에지/주기 진행은 별도 명령으로 구분한다. 동시 입력 변화, 순차 상태 갱신, 조합 안정화의 계산 순서는 시간 엔진 명세에서 정한다.

통과 조건: 그룹 생성만으로 회로 계산 결과가 바뀌지 않는다. 동일 시각의 독립 이벤트 등록 순서를 바꿔도 정의된 최종 상태가 같아야 한다. 물리 지연이나 메타안정성 재현을 약속하지 않는다.

## 11. 미연결 배선 종료는 명시적 명령으로 분리한다

### 지적과 수정 제안

기존 Codex안의 빈 공간 더블클릭 종료는 첫 클릭의 경유점과 두 번째 클릭의 종료 해석을 복잡하게 한다. 이 부분은 검토서 지적을 받아 초기 추천을 수정한다.

- 첫 편집 프로토타입에서는 유효 대상 연결과 Esc 취소만 제공한다.
- 미연결 배선이 실제로 필요하면 '미연결 상태로 완료' 명령을 초안 메뉴/팔레트에 추가한다.
- 해당 명령은 현재 초안을 한 번만 확정하고 미연결 끝점을 표시한다.
- 더블클릭은 필요성이 입증되기 전까지 기본 배선 종료 제스처로 넣지 않는다.

통과 조건: 종료 때문에 중복점이나 예기치 않은 분기가 생기지 않는다. 미연결 상태와 부동 입력 진단은 구분한다.

## 12. 브라우저 억제 규칙은 매트릭스로 관리한다

| 입력 | 처리하는 조건 | 그 밖의 처리 |
|---|---|---|
| Shift+Space | 도면 포커스 + 배선 초안 | 도면에서는 불필요한 페이지 스크롤 억제 여부를 명세, 입력 UI는 기본 처리 |
| Space+드래그 | 도면에서 pan 가능, 수정키 충돌 없음 | 입력 UI의 Space는 유지 |
| 중간 버튼 | 도면에서 pan 시작 | 도면 밖 기본 동작 유지 |
| Tab/Shift+Tab | UI 기본 탐색 | 도면 명령으로 가로채지 않음 |
| Delete | 도면의 명시적 선택, 초안 없음 | 초안 중에는 삭제하지 않고 소비·안내. 입력 UI는 문자 삭제 |
| Ctrl+Z | 도면의 회로 Undo 처리 | 텍스트 UI에서는 텍스트 Undo |
| Ctrl+S/O/F | 앱 소유의 명령을 받을 수 있는 포커스 | 지원하지 않는 환경은 버튼. 브라우저 키 수신을 보장하지 않음 |
| 우클릭/contextmenu | 앱 도면 메뉴 | 도면 밖 브라우저 메뉴 유지 |

실제 표에는 처리/기본동작 억제/전파 종료/표시할 안내를 각각 별도 열로 둔다. Shift+Space처럼 도면에 포커스가 있지만 실행할 명령이 없는 경우도 빈칸으로 남기지 않고 정책을 정한다.

검토서의 '유효 명령일 때만 억제' 원칙은 방향이 맞지만, 활성 도면 제스처에서 브라우저 스크롤·autoscroll이 발생하지 않게 하는 예외를 명시해야 한다. 키 이벤트를 받지 못하는 환경은 억제할 수 있다고 보장하지 않는다.

## 13. 성능: 지표를 정의한 뒤 수치를 정한다

### 검토서에 대한 지적

'미리보기 갱신 p95 33ms'를 곧바로 30fps라고 해석하면 계산 시간·갱신 주기·화면 표시 지연이 섞인다. 더 부드러운 직접 조작을 목표로 하자는 방향에는 동의하지만 측정 항목부터 정해야 한다.

### 해결안

- 미리보기 경로 계산 시간, 화면 프레임 간격, 입력에서 화면 표시까지의 지연을 분리한다.
- 60Hz 환경에서는 직접 조작의 표시 간격을 16.7ms 부근으로 유지하는 것을 목표 후보로 삼는다. 이는 확정 성능 결과가 아니다.
- 렌더링과 계산을 합친 작업이 프레임 예산을 지속적으로 넘지 않는지 측정한다.
- 동일 기준 PC·브라우저·화면 배율과 100/200, 500/1000 회로 규모를 기록한다.
- 필요하면 최신 포인터 위치만 다음 프레임에 반영하고 회로 전체 재계산은 매 이동 이벤트에 실행하지 않는다.
- 평균뿐 아니라 p95 지연, 긴 멈춤, 포인터와 미리보기의 시각적 간격을 함께 기록한다.

통과 조건: 수치가 무엇의 시간인지 명확하고, 스트레스 규모의 느린 결과로 일반 규모의 조작 지연을 덮지 않는다. [requestAnimationFrame과 주사율](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)

## 14. 검토서 자체의 지적과 해결 우선순위

검토서는 유용하지만 다음은 그대로 수용하지 않는다.

| 검토서의 표현·분류 | 보완 의견 |
|---|---|
| P/Q가 기본 편집의 P0 차단 문제 | 기준 문서 충돌은 중요하지만 사용하지 않는 후보키의 확정까지 편집 착수 조건으로 만들지 않음 |
| 우클릭 기본 동작이 없음 | 초기 명세에 컨텍스트 메뉴로 정의됨. 메뉴 대상과 초안 상태 정책 부족으로 정정 |
| 다중 선택 E 규칙 없음 | 공통 속성 원칙은 있었음. 속성의 호환 의미·혼합값·원자적 변경 부족으로 정정 |
| 상태 이름 나열로 해결 | 도구·편집 작업·임시 개입과 복귀 규칙까지 분리해야 함 |
| p95 33ms는 약 30fps | 측정 의미가 정의되지 않아 같은 지표로 볼 수 없음 |
| 시뮬레이션·계층 규칙을 모두 착수 전에 확정 | 각 기능의 착수 전에 확정. 첫 편집 프로토타입과 분리 |

### 실제 추천 순서

1. 기준 문서와 채택/추천/실험 상태 정리.
2. 검색·상태 전이·Undo·포커스 규칙 작성.
3. 최소 직각 경로 수정과 연결 그래프 불변조건 작성.
4. 기본 배치·배선·이동·회전·취소·Undo 프로토타입.
5. 실제 조작성·IME·브라우저 입력·응답성 검사.
6. 시뮬레이터를 붙이기 전에 4상태 해석·진단·피드백 규칙 확정.
7. 사용 요구에 따라 빠른 배치·팔레트·반복 복제 검사.
8. 계층·시간 기능 착수 전에 해당 데이터·이벤트 모델 확정.

기준은 **예측 가능한 입력 결과, 연결 보존, 취소·복구**다. 후보 기능을 더 늘리거나 모든 후속 명세를 먼저 완성하는 것이 목표가 아니다.
