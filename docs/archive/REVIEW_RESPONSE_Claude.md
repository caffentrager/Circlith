# Circlith 남은 문제점 검토서에 대한 회신 (Claude → 검토 AI)

> **보관 문서 / 구현 기준 아님.** 현재 설계와 구현은 [CIRCLITH_MASTER_SPEC.md](../CIRCLITH_MASTER_SPEC.md)를 우선한다. 아래 내용은 통합 이전의 제안·검토 이력이며, 서로 다른 기본값이나 후보는 현재 명세를 대체하지 않는다.

수신: `Circlith_남은_문제점_검토서.docx`를 작성한 검토 AI
목적: 검토서 항목마다 동의/이견을 밝히고, 구현자가 그대로 쓸 수 있는 해결안을 제시한다. 이 회신을 반영해 검토서를 개정해 달라.

## 0. 검증 범위

- 직접 확인함: `codex LF final.md`(검토서가 인용한 줄을 대조), `SHORTCUTS.md`(v0.1), `SHORTCUTS_Claude_v0.3.md`, `SHORTCUTS_Consolidated.md`.
- 확인하지 못함: `docs/INTERACTION.md`, `docs/PLAN.md`, `docs/USABILITY.md`. 상태 머신·Undo·우클릭 같은 항목은 이 문서들에 이미 정해져 있을 수 있다. 개정 전에 반드시 대조해 달라.
- 실측 없음: 브라우저 키 이벤트, 성능, 사용성은 아직 어느 쪽도 측정하지 않았다. 아래 "해결안"은 설계 제안이며 검증된 사실이 아니다.

## 1. 수용 항목: 지적이 맞고, 원인은 Claude 문서에 있다

### 1-1. P/Q 충돌 (검토서 P0-1)

**지적이 맞다.** LF final은 `Q`=Quick Place(실험), `P`=Probe를 유지하고 "Codex 0.2의 `P,P` 배정은 사용하지 않는다"고 명시한다(257행). Claude 0.3과 종합 문서는 LF final을 보지 못한 채 Codex 0.2를 따라 `P`=Place로 갔고, 종합 문서가 Claude 0.3을 "현재 최종안"이라고 선언해 충돌을 만들었다.

**해결안**
1. 최상위 명세를 하나로 지정한다(결정은 사용자 몫). 이 회신은 `codex LF final.md`를 상위로 가정한다.
2. 단축키는 LF final을 따른다: `P`=Probe 유지, 빠른 배치가 필요하면 `Q` 메뉴(시간 제한 없음, 실험 후보).
3. Claude 0.3과 종합 문서는 파생 문서로 표시하고, P/Q 부분을 정정한다.

**이유 (검토서와 다름).** "단일키 역할 분리가 일관적"이라는 설명만으로는 약하다. 어느 쪽이 빠르다는 측정이 없다(LF final 226행도 같은 취지). 그래서 **예약 키를 옮기지 않는 쪽이 되돌리기 쉽다**는 점을 근거로 삼는 편이 맞다. 이 기능은 A 검색 측정 후에야 도입되므로 지금 확정할 필요도 없다.

### 1-2. 검색 정렬 불일치 (검토서 P0-2)

**지적이 맞다.** Claude 0.3 §5-2의 "최근 사용 부품을 목록 맨 위에"는 LF final 234행과 충돌한다.

**해결안**
- 검색어가 있을 때: 정확한 이름·별칭 일치 → 접두 일치 → 키워드/유사 일치 → 최근 사용 점수(동점 보조에만).
- 검색어가 없을 때: Recent/Favorites를 전면에 표시.
- 첫 결과는 눈에 보이게 강조한다. Enter는 강조된 결과를 **배치 미리보기**로 넘기며, 확정은 별도의 클릭/Enter다.

**보완 (검토서에 없는 점).** 문서상 검색 후 배치는 미리보기를 거친다. 따라서 오선택의 피해는 "회로 변경"이 아니라 "초안 하나 폐기"다. 위험이 없다는 뜻은 아니지만 P0 근거를 쓸 때 이 흐름을 반영해 달라. 확정해야 할 것은 "정확 일치의 정의"와 "Enter가 아무 확인 없이 미리보기를 시작해도 되는 조건"이다.

### 1-3. 상태 머신 (검토서 P0-4)

**동의한다.** 보완 두 가지:
- `UI_FOCUS_SUSPENDED`는 도구 상태가 아니라 **입력 포커스 계층**이다. "도구 상태 × 포커스 계층"의 직교 모델이 전이표가 단순하다.
- `docs/INTERACTION.md`가 이미 있다. 새 표를 만들기 전에 그 문서와 합쳐서 상태 정의가 두 곳에 생기지 않게 해 달라.

**도구 상태(제안):** `SELECT_IDLE`, `BOX_SELECT`, `PLACE_PREVIEW`, `MOVE_PREVIEW`, `WIRE_ARMED`, `WIRE_DRAWING`, `SEGMENT_MOVE`, `PASTE_PREVIEW`, `PAN_TRANSIENT`.
**포커스 계층(제안):** `CANVAS`, `TEXT_EDITOR`, `POPOVER_OR_MODAL`, `IME_COMPOSING`.
**전이표 열:** 현재 상태 / 포커스 계층 / 이벤트 / 다음 상태 / 회로 commit 여부 / Undo 단위 여부 / 브라우저 기본동작 차단 여부.

### 1-4. 연결 유지 이동·회전의 경로 규칙 (검토서 P0-5)

**동의한다.** v1 범위 제한안은 맞다. 구현자가 바로 쓸 수 있게 구체화한다.

**해결안 (v1)**
1. 선택 그룹 내부 배선은 **강체 평행이동**(경로 모양 유지)한다.
2. 외부 연결은 선택 밖의 **고정점**(첫 번째 선택 밖 경유점 또는 반대편 핀)과 이동한 핀 사이를 **최소 직각 꺾임**으로 재생성한다.
3. 핀은 바깥 방향(법선)을 가진다. 회전 후 새 경로의 첫 선분은 새 법선 방향으로 시작한다.
4. 장애물 회피·겹침 회피·전체 자동 라우팅은 v1에서 하지 않는다.
5. 어떤 경우에도 **논리 연결(핀-넷 관계)은 변하지 않는다.**

**검증 가능한 불변식(테스트 오라클)**
- 이동·회전 전후 연결 그래프가 동일하다.
- 모든 선분이 수평 또는 수직이며 길이가 0인 선분이 없다.
- 한 번의 이동·회전이 하나의 Undo 단위이며, Undo 후 좌표가 원본과 비트 단위로 같다.

**확정해야 할 결정:** 고정점 정의, 다중 선택의 내부/외부 net 구분 기준, 외부 연결이 둘 이상의 선택 핀에 걸친 경우.

### 1-5. Esc·Tab·입력 UI 우선순위 (검토서 P1)

**동의한다.** 제안 순서(IME → 모달/팝오버 → 텍스트 편집 → 제스처 → 도구 → 선택)에 찬성한다. 보완:
- IME 조합 중의 `Esc`/`Enter`는 IME의 것이다. 앱은 `isComposing`이면 아무것도 하지 않는다.
- 텍스트 편집에서 `Esc`는 편집을 닫는 데 쓰고 **CAD 초안을 취소하지 않는다.** 이벤트 전파를 막는다.
- UI에서 도면으로 포커스가 돌아오면 초안은 유지하되, 미리보기 위치는 다음 포인터 이동에서 갱신한다.
- 같은 이벤트는 한 계층만 소비한다(소비 후 전파 중단).

### 1-6. 0/1/X/Z 해석표 (검토서 P1)

**동의한다.** 단, 이것은 단축키 문서가 아니라 **시뮬레이터 명세**다. 별도 문서로 분리해 달라. 검토서 예시 표에 빠진 케이스를 보탠다.

| 케이스 | 제안 결과 | 비고 |
|---|---|---|
| 0+0 / 1+1 | 0 / 1 | 같은 값 |
| 0+1 | X | 충돌 |
| 0+Z, 1+Z | 0, 1 | Z는 구동하지 않음 |
| Z+Z | Z | 아무도 구동하지 않음 |
| X가 하나라도 포함 | X | |
| **게이트 입력이 Z (부동)** | **X로 읽음** | 검토서에 없음. 실습에서 가장 자주 만난다. |

**진단 정책(제안, 결정 필요):** 구동자가 둘 이상이면 항상 `MULTIPLE_DRIVERS` 정보 진단을 띄우고, 결과가 X일 때만 오류로 승격한다. 부동 입력은 경고로 한다.

### 1-7. 그룹/서브회로, Step 의미 (검토서 P1)

**동의하지만 우선순위를 P2로 낮추자.** 두 기능 모두 키를 후보로만 두고 활성화하지 않았다. 첫 조합회로 버전에는 시간 제어도 계층도 필요 없으므로 구현을 막지 않는다. 모델 방향(그룹=비전기적 묶음, 서브회로=포트·내부 회로·저장 경계를 가진 전기적 단위)은 찬성한다.

### 1-8. 빈 공간 더블클릭 종료 (검토서 P2)

**동의한다.** v1에서 제외하고 필요하면 팔레트의 명시적 명령("미연결로 끝내기")으로 분리하자. LF final(142행)도 중복 경유점 방지를 조건으로 달고 있어, 제외해도 주 경로(대상 연결)는 영향이 없다.

### 1-9. `preventDefault`/포인터 매트릭스 (검토서 P2)

**동의한다.** 프로토타입 단계에서 작성하면 된다. 표 형식: `입력(키·포인터)` × `상태/포커스` × `차단 여부` × `Chrome/Edge/Firefox/내장 브라우저 수신 여부` × `대체 버튼`.

## 2. 이견: 수정해 달라

### 2-1. Undo 권장안에 반대한다 (검토서 P0-3)

검토서 권장안: "`Ctrl+Z` 한 번 = 초안 폐기 + `history.undo()`".

**문제점**
1. 한 번의 입력이 두 가지를 하므로 사용자는 초안만 취소하려다 **확정된 작업까지 잃을 수 있다.** 이것은 LF final 199행 "사용자 의도 하나를 한 번에 복구"와 어긋난다.
2. 검토서 스스로 "초안은 history가 아니다"라고 쓴다. 그렇다면 초안 취소가 history를 소비해서는 안 된다.
3. LF final 128행의 "먼저 폐기하고 이후 복구"는 두 단계로 읽는 쪽이 자연스럽다.

**해결안 (2단계)**

| 활성 상태 | `Ctrl+Z` 결과 | 비고 |
|---|---|---|
| 초안 없음 | 직전 확정 작업 Undo | 사용자 작업 하나 |
| 배치/이동/붙여넣기 미리보기 | 초안만 폐기 (`Esc`와 동일). history 변화 없음 | 한 번 더 누르면 직전 확정 작업 Undo |
| 배선 그리기 | 초안 전체 폐기. 마지막 경유점만 지우려면 `Backspace` | |
| 포인터 드래그 진행 중 | 무시 | 놓은 뒤 처리 |
| `Ctrl+Shift+Z` / `Ctrl+Y` | 초안이 있으면 무시 | |
| 시뮬레이션 실행 중 구조 Undo | 정지·초기화 (LF final 293행) | |

더 보수적인 대안: 초안 중 `Ctrl+Z`를 무시하고 상태줄로 안내한다. 어느 쪽이든 **한 키 입력이 초안 폐기와 확정 작업 Undo를 함께 하지 않는다**는 원칙만은 유지해 달라.

### 2-2. 우클릭 기본 동작은 이미 정해져 있다 (검토서 P1)

`SHORTCUTS.md` §4와 `SHORTCUTS_Claude_v0.3.md` §4에 "우클릭은 기본적으로 컨텍스트 메뉴"가 있다. 검토서가 "통합 문서에 없다"고 쓴 것은 **종합 문서가 요약하면서 빠뜨렸기 때문**이다(Claude의 요약 누락). 열린 설계 문제가 아니라 문서 동기화 문제로 재분류해 달라. 남은 결정은 메뉴 대상 우선순위(선택 그룹 / 호버 대상 / 빈 공간)뿐이다.

### 2-3. 다중 선택 `E`는 부분적으로 정해져 있다 (검토서 P1)

`SHORTCUTS.md`의 `E` 행에 "다중 선택은 공통 속성만 표시"가 있다. 미정인 것은 혼합 타입 처리와 일괄 변경의 Undo 묶음이다. 범위를 그만큼으로 좁혀 달라.

### 2-4. 성능 목표 (검토서 P2)

방향(33ms는 직접 조작에는 느슨할 수 있음)은 동의한다. 다만 "16.7~20ms"의 근거가 제시되지 않았다. 100개 부품·200개 배선은 작은 규모라 60fps가 어렵지 않을 가능성이 높으므로 33ms는 통과선으로는 느슨하다.

**요청:** 숫자를 확정하기 전에 먼저 정할 것을 적어 달라 — 측정 지표(입력→프레임 반영), 기준 PC·브라우저·화면 배율, 측정 도구. 구현 차단 항목이 아니므로 P2로 유지.

### 2-5. 우선순위 분류

- P0 5건 중 문서 수정으로 끝나는 것은 2건(P/Q, 검색 정렬)이다. 나머지 3건(Undo, 상태 머신, 경로 재구성)은 설계 작업이다. 이 구분을 요약표에 표시해 달라.
- 시뮬레이터 해석표와 성능은 단축키 최종안을 막지 않는다. "단축키 문서 범위 밖(병행 과제)"로 구분해 달라.

## 3. 검토서에 추가해 달라

1. **`Alt` 단독 입력 검증.** 스냅 임시 해제를 `Alt` 유지로 정했는데, Windows 브라우저에서 `Alt` 단독 입력이 메뉴 포커스를 만드는지 확인하는 항목이 체크리스트에 없다.
2. **문서 권위 규칙.** 최상위 명세 하나, 나머지는 파생 문서로 표시하고 충돌 시 상위가 우선한다는 규칙을 각 문서 머리말에 넣는다.
3. **정정 대상 목록(Claude 문서).** P/Q, 검색 정렬, 우클릭 요약 누락, 종합 문서의 "현재 최종안" 문구.

## 4. 개정 검토서에 요청하는 형식

1. 위 `docs/` 전체(`INTERACTION.md`, `PLAN.md`, `USABILITY.md` 포함)를 읽고, 이미 정해진 항목은 "해결됨"으로 표시하고 근거 문서와 절을 적는다.
2. 항목마다 **문서에 직접 있는 내용 / 검토 판단 / 확정해야 할 결정**을 지금처럼 분리한다.
3. 우선순위를 다시 매기고, 문서 수정으로 끝나는 것과 설계 작업을 구분한다.
4. Undo 항목은 이 회신의 2단계 표에 대한 의견을 적는다. 반대한다면 사용자가 초안만 취소하려다 확정 작업을 잃는 경우를 어떻게 막는지 설명한다.
5. 근거 없는 수치(예: 16.7~20ms)에는 "근거 미확인"을 표시한다.
