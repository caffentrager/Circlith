> **보관 문서 / 구현 기준 아님.** 현재 설계와 구현은 [CIRCLITH_MASTER_SPEC.md](../CIRCLITH_MASTER_SPEC.md)를 우선한다. 아래 내용은 통합 이전의 제안·검토 이력이며, 서로 다른 기본값이나 후보는 현재 명세를 대체하지 않는다.

작성일: 2026-10-13. Windows 데스크톱의 웹 CAD를 기준으로 한 설계 제안이다. 앱 구현과 실제 사용자 검증은 아직 진행하지 않았다. 어느 세트가 더 빠른지, 조작성이 검증됐는지는 이 문서가 주장하지 않는다.

## 0. v0.2 → v0.3 한눈에 보기

Codex 0.2의 지적 중 수용한 것과 근거는 다음과 같다. 수용하지 않은 항목은 없다.

| 항목 | Claude v0.2 | Codex 0.2 | v0.3 결정 | 이유 |
|---|---|---|---|---|
| 빠른 배치 키 | `Q` 접두사(실험), P는 Probe 단일 키 | `P`=Place 메뉴, 항목 안에서 `P,P`=Probe | **`P`=Place 메뉴 채택(후보)**, `Q` 폐기 | `Q`는 `P`가 Probe로 선점돼 있어서 쓴 우회책이었다. `P`는 KiCad·Altium의 Place와 의미가 같고 [K][A], Probe는 아직 구현 전이라 옮기는 비용이 없다. |
| 메뉴 시간 제한 | 1.5초 | 필수 시간 제한 없음 | **시간 제한 없음** | 시간 제한이 있으면 느린 사용자가 메뉴를 놓친다. 두 번째 키·클릭·`Esc`로 종료하는 쪽이 오작동이 적다. |
| 포트 Input/Output | `P,I` / `P,Shift+I` | 키 미정, 메뉴 항목·A 검색으로 접근 | **키 미정** | 방향 전환과 논리 반전은 다른 개념이다. `Shift` 반전 규칙은 게이트 쌍에만 쓴다. |
| 직전 도구 재실행 | `Enter`(대기 상태) | 기본 `Enter` 확정과 분리, 별도 명령 | **`Enter`에서 제거, 명령 팔레트의 명령으로** | 키 반복 입력이 새 도구를 연속 시작할 위험이 있다. |
| Step 키 | `Ctrl+.`=클록 스텝 | `Shift+Enter`=이벤트 스텝, 클록은 별도 명세 | **`Shift+Enter`=다음 이벤트 1개, `Ctrl+.` 폐기** | 이벤트와 클록 주기를 구분해 명세해야 한다. 클록 1주기는 별도 명령으로 두고 키는 미정. |
| 그룹·서브회로 키 | `Ctrl+G`, `Shift+G`, `Ctrl+↑/↓`를 예약 | 키 미확정, 메뉴 우선 | **키 미확정 후보로 강등** | 그룹과 서브회로의 데이터 의미가 정해지기 전에 키를 고정하지 않는다. |
| 간격 반복 복제 | `Ctrl+D` 반복 | 같은 변위 제안 기능으로 분리, 기본 `Shift+D` | **`Shift+D` 반복 복제로 채택, `Ctrl+D`는 호환 후보** | 키와 기능을 분리하고, 브라우저 처리는 실측 후 결정한다. |
| 명령 팔레트 | `/` (v0.2에서는 제외) | `/` 추가 제안 | **채택(후보)** | 단축키를 외우지 않은 명령, 키가 없는 명령(정렬·직전 도구·클록 스텝 등)의 공통 진입점이 된다. |
| Net Label | `N`(v0.1 따름) | `N` 기본 + `L` 호환 별칭 후보 | **`N` 기본, `L`은 별칭 후보** | 두 키는 같은 명령을 호출한다. |
| 보기 맞춤 `Z` | 없음 | 선택 영역 보기 후보 | **후보로 추가** | `Shift+Home`과 같은 명령이다. 선택 없음일 때의 동작은 검증한다. |
| 우클릭 드래그 팬 | 없음 | 선택 설정 후보, 짧은 우클릭은 메뉴 | **설정 후보로 추가** | 기본은 `Space`+드래그와 휠 버튼. |
| 핀 클릭 배선 시작 | `W`로만 시작 | 핀 클릭 시작을 빠른 조작 후보로 | **후보로 추가** | 핀 선택과의 우선순위 규칙이 먼저 필요하다. |
| `M`/`G` | `M`=연결 유지 이동, `G`=그리드 | 동일 | **유지(잠정)** | 두 Codex 문서와 기존 Circlith 초안이 같은 방향이다. 사용성 검사로 재확인한다. |

표현 원칙은 Codex 0.2 "근거와 표현에서 수정할 사항"을 따른다.
- 같은 키를 쓴다고 학습 비용이 0이라고 쓰지 않는다. KiCad의 `M`/`G`와 Circlith의 `M`은 의미가 다르다.
- 브라우저 충돌을 절대 표현으로 쓰지 않는다. Chrome의 `Ctrl+E`는 검색, `Ctrl+D`는 북마크, `Ctrl+Enter`는 주소창에서 동작이 다르다 [C].
- 물리 키 판정(`event.code`)만으로 IME 안전성을 보장하지 않는다. 입력 필드·조합 상태·포커스 보호가 함께 필요하다 [M].
- 논리 CAD에 도형·핀 편집이 불필요하다고 단정하지 않는다. 초기 범위 제외와 장기 필요 여부를 구분한다.
- 시간이 절약된다는 주장은 측정 후에만 쓴다.

## 선정 기준과 근거의 범위

- 부품 추가·배선·이동·회전·속성처럼 반복하는 작업에는 단일 키를 배정한다.
- CAD의 기존 관습을 참고하되, 초보자의 연결 손실과 웹 브라우저 충돌을 줄이는 쪽을 우선한다.
- Shift는 반대 방향, 추가 상태 또는 빠른 이동처럼 원래 작업의 변형에 사용한다. 모든 조합에 이 규칙이 적용되는 것은 아니다.
- 키의 이름은 기억을 돕는 수단이다. 손 위치만으로 작업 속도가 빠르다고 판단하지 않는다.
- 아래 '관습'은 출처에서 확인한 선례다. '설계 판단'은 Circlith에 맞춘 제안이며 업계 표준이나 측정된 효과를 뜻하지 않는다.
- 첫 버전에 필요한 키와 후속 기능의 키를 분리한다. 기능이 없으면 예약한 키도 가로채지 않는다.
- 키가 없는 명령은 `/` 명령 팔레트와 메뉴로 접근한다. 모든 명령에 키를 배정하지 않는다.

**처음 익힐 세트:** A, W, M, R, E, V, Esc, Backspace, Ctrl+Z, Space+드래그. 나머지는 작업 중 상태줄과 메뉴에서 발견할 수 있도록 한다.

## 1. 첫 버전: 부품·편집

| 키 | 기능과 적용 범위 | 이 키를 추천하는 이유 |
|---|---|---|
| A | 부품 검색창 열기. 검색 후 부품 배치 미리보기 | Add의 첫 글자이고 KiCad·LibrePCB에 선례가 있다 [K][L]. 부품 종류별 키를 외우기 전에 하나의 진입점을 익히게 한다. |
| W | 배선 도구. 연결 가능한 핀/선분 위에서 누르면 그 위치에서 바로 시작 | Wire의 첫 글자이고 KiCad·EasyEDA·LibrePCB에 선례가 있다 [K][E][L]. 빈 공간에서는 배선 대기만 시작해 의도하지 않은 초안을 만들지 않는다. |
| V | 선택 도구로 돌아가기. 진행 초안은 취소하고 기존 선택은 유지 | 기존 Circlith 초안을 유지한다. 시뮬레이션·회로 저장과 연상되는 S를 비워두고, W와 다른 고정 도구를 한 키로 부른다. 회로 CAD 전체의 공통 표준이라는 주장은 하지 않는다. |
| M | 부품/선분 이동 미리보기. 연결 유지가 기본 | Move의 첫 글자라 기억하기 쉽다. 연결 보존 작업을 M과 G 중에서 고르는 부담을 줄인다. KiCad의 M은 연결을 유지하지 않고 G가 유지하므로, Circlith의 M은 의도적으로 의미가 다르다 [K]. |
| R | 선택 대상 또는 배치 초안을 반시계 방향 90° 회전 | Rotate의 첫 글자이며 KiCad·LibrePCB에 선례가 있다 [K][L]. Space를 회전에 쓰지 않아 화면 이동과 구분한다. |
| Shift+R | 시계 방향 90° 회전 | R의 반대 방향을 Shift로 묶고 LibrePCB와 같은 방향 쌍을 사용한다 [L]. 네 번 돌려 원하는 방향을 찾는 조작을 줄이려는 설계다. |
| E | 속성 편집. 단일 대상은 패널 열기, 다중 선택은 공통 속성만 표시. 배치 초안에도 사용 가능(입력 개수·비트 폭 등) | Edit의 첫 글자이며 KiCad·LibrePCB에 선례가 있다 [K][L]. 더블클릭의 대안이다. Tab을 포커스 이동으로 남겼으므로 배치 직전 설정도 E로 연다. |
| F2 | 선택한 단일 부품 이름 또는 문자 직접 편집 | Altium의 선택 문자 직접 편집 선례를 이름 편집으로 확장한다 [A]. E는 전체 속성, F2는 이름/내용 하나로 역할을 구분한다. 이름 필드가 없으면 실행하지 않는다. |
| Shift+D | 선택 대상 복제 후 커서에 붙여 배치 미리보기. **연속 복제 시 직전과 같은 변위를 제안(v0.3)** | Duplicate의 D를 유지하되 Chrome의 북마크 Ctrl+D를 피한다 [C]. 회로 CAD 공통 관습은 아니며, 선택이 없으면 아무것도 복제하지 않는다. 같은 변위 제안은 EasyEDA의 Repeat, Altium의 반복 복사 선례와 방향이 같다 [E][A]. N비트 슬라이스처럼 같은 간격으로 늘리는 작업에 쓴다. |
| Delete | 선택한 대상 삭제 | 벤치마크 CAD들이 공통으로 사용하는 삭제 키다. 커서 아래 대상을 직접 지우지 않아 오삭제를 줄인다. |
| 방향키 | 선택 대상을 그리드 1칸 이동 | 방향 자체로 결과를 예상할 수 있다. Altium의 커서 이동 대신 선택 대상을 직접 움직이는 Circlith 설계다. 연결을 유지하며, 선택이 없으면 아무것도 이동하지 않는다. |
| Shift+방향키 | 선택 대상을 그리드 10칸 이동 | 작은 이동과 큰 이동을 같은 방향키에 묶는다. 10칸은 Altium의 이동 증분 선례를 참고했다 [A]. 실제 선호 증분은 검증한다. |

방향키 반복 입력은 한 번 누르고 놓는 동안 하나의 이동 작업으로 묶는다. 텍스트 입력 중에는 커서 이동, 배치 초안 중에는 초안 이동으로 처리하며 확정 회로를 따로 움직이지 않는다.

**간격 반복 복제 규칙 (v0.3):** 첫 복제 위치를 확정한 뒤 `Shift+D`를 다시 누르면 같은 변위의 복제 미리보기를 제안한다. 확정한 복제 하나가 Undo 한 단계다. 배치를 취소하면 기억한 변위는 유지하되 회로는 바꾸지 않는다. 선택이 바뀌면 변위 기억을 지운다.

## 2. 첫 버전: 배선·취소

| 키 | 기능과 적용 범위 | 이 키를 추천하는 이유 |
|---|---|---|
| Shift+Space | 배선 초안의 가로 우선/세로 우선 꺾임 전환 | 왼손으로 누르기 쉬운 조합을 후보로 삼는다. Tab을 포커스 이동으로 남기고, Space 단독+드래그의 화면 이동과 수정키로 구분한다. Circlith의 자체 배정이며 Altium의 같은 키가 동일 기능이라는 뜻은 아니다. |
| Backspace | 배선 중 마지막 경유점 제거. 경유점이 없으면 초안 취소 | 방금 입력한 내용을 뒤로 되돌리는 의미와 일치하고 Altium 배선에도 선례가 있다 [A]. Delete까지 같은 역할로 쓰면 확정 객체 삭제와 혼동하므로 초안에서는 Delete를 소비하되 삭제 명령은 실행하지 않는다. |
| Enter | 배치·붙여넣기·키보드 이동 미리보기 확정. 배선 중에는 강조된 유효 대상에 연결 | 클릭 확정의 키보드 대안이며 Altium의 Enter=클릭 선례를 참고한다 [A]. 유효한 연결 대상이 없으면 Enter로 미연결 배선을 만들지 않는다. 대기 상태의 Enter는 새 도구를 시작하지 않는다(v0.3). |
| Esc | 진행 작업 하나 취소 → 배선 대기 종료 → 선택 해제 | 여러 CAD가 취소에 사용하는 키다. 먼저 가장 가까운 작업을 취소해 회로 전체에 영향을 주지 않는다. 실행 중 시뮬레이션 정지와 혼용하지 않는다. |
| Alt 유지 | 배치·이동·배선에서 그리드 스냅만 임시 해제 | 설정을 켜고 끄는 두 번의 조작 없이 정밀 배치할 수 있다. Ctrl의 선택·클립보드 역할과 Shift의 연속 배치 역할을 비켜간다. 핀/접속점 스냅과 연결 확정은 유지한다. Windows 브라우저에서 Alt 단독 입력이 메뉴 포커스를 만들지 않는지 검증한다. |
| Shift+클릭 | 배치 중: 연속 배치. 선택 도구에서는 선택 상태 토글 | 원래 조작의 확장으로 이해할 수 있다. 선택 토글은 Altium 선례가 있다 [A]. 도구 상태가 명확할 때만 의미가 바뀌며 배선 진행에서는 연속 부품 배치로 처리하지 않는다. |
| Tab / Shift+Tab | 화면 버튼·패널·입력 필드의 다음/이전 포커스로 이동 | 브라우저 기본 탐색을 유지한다 [C]. 이전 Circlith 초안의 Tab=배선 꺾임 전환을 변경한다. 입력 필드에 포커스가 가면 도면 단축키는 멈춘다. |

Shift+Space는 도면에 포커스가 있고 배선 초안이 있을 때만 가로챈다. 이를 누른 이벤트는 Space 화면 이동을 시작하지 않는다. 일반 Space+드래그로 화면을 이동하는 동안에는 배선 초안을 잠시 유지하고 편집 클릭을 소비하지 않는다.

Tab으로 포커스가 이동하는 것은 의도적인 UI 탐색이다. 초안은 잠시 유지하고 Esc/도면 재포커스로 돌아갈 수 있게 한다. 창이 비활성화되거나 포인터 캡처를 잃으면 기존 명세대로 제스처를 롤백한다.

### 5-2. 확장 후보: 배치·명령 발견 (검증 통과 전에는 활성화하지 않음)

Place 메뉴와 `/` 팔레트는 'A 검색만으로 충분한지'를 측정한 뒤 도입 여부를 확정한다. 아래 순서로 단계적으로 시도한다.

**1단계. A 검색 보강.** A 검색창에 `and`, `nand`, `in`, `out`, `0`, `1` 등 짧은 이름을 입력하면 해당 부품이 첫 결과로 나오고 Enter로 바로 배치 미리보기를 시작한다. 최근 사용 부품을 목록 맨 위에 둔다. 새 키가 필요 없다.

**2단계. `P` Place 메뉴.**

- P를 누르면 두 번째 키와 대상 이름을 보여주는 메뉴를 연다.
- **필수 시간 제한을 두지 않는다.** 두 번째 키, 항목 클릭 또는 Esc로 종료한다.
- 메뉴가 열린 동안의 두 번째 키는 일반 도면 명령과 구분한다. A는 AND 배치이며 부품 검색창을 열지 않는다.
- 선택한 항목은 곧바로 회로를 변경하지 않고 배치 미리보기를 시작한다.
- Shift를 누른 두 번째 키는 게이트의 출력 반전 쌍에만 사용한다. 입력/출력 포트까지 같은 반전 규칙으로 설명하지 않는다.
- 입력 필드와 모달에서는 열지 않는다.

| 시퀀스 | 대상 | 근거 및 결정 상태 |
|---|---|---|
| P, A / P, Shift+A | AND / NAND | 기본 게이트와 출력 반전 쌍을 묶는 Circlith 자체 설계. 채택 후보. |
| P, O / P, Shift+O | OR / NOR | 같은 규칙. |
| P, X / P, Shift+X | XOR / XNOR | 같은 규칙. |
| P, B / P, Shift+B | Buffer / NOT | 같은 규칙. P, N을 NOT 별칭으로 둘지는 검증한다. |
| P, M | MUX | 이름 연상. 기능 지원 시 활성화한다. |
| P, F | D 플립플롭 | 이름 연상. 순차회로 지원 시 활성화한다. |
| P, C | Clock | Clock의 첫 글자. 시간 시뮬레이션 단계의 후보. |
| P, 0 / P, 1 | 상수 0 / 1 | 값 자체가 대상 이름이라 기억하기 쉽다. |
| P, P | Probe | P 단일 키 예약을 메뉴 안으로 옮겨 충돌을 해소한다. |
| P, S | 서브회로 | 계층 기능 도입 시 검토한다(§5-4). |
| Input / Output | 키 미정 | 메뉴의 명시적 항목 또는 A 검색(`in`, `out`)으로 접근한다. |

**3단계. `/` 명령 팔레트.** 명령 이름을 검색하고 실행한다. A는 부품 찾기, `/`는 명령 찾기로 역할을 나눈다. 팔레트에는 이름과 현재 배정 키를 함께 표시하고, 현재 상태에서 실행할 수 없는 명령은 이유를 알려준다. 입력 필드에서 `/`를 입력해도 팔레트를 열지 않는다. Fusion의 `/` Command Line을 참고한 설계이며 [F], 키가 없는 명령(§5-4)의 공통 진입점이 된다.

| 직전 도구 재실행 | 팔레트 명령 | 기본 Enter 확정과 분리한다. 키는 반복 사용 빈도를 측정한 뒤 결정한다. LibrePCB의 '우클릭=직전 도구'가 선례다 [L]. |
| 클록 1주기 Step | 팔레트 명령 | 이벤트 Step과 의미를 구분해 명세한 뒤 키를 정한다. |
| Input/Output 배치 키 | 메뉴·A 검색 | 방향 전환과 논리 반전을 같은 규칙으로 설명하지 않는다. |

## 6. 키보다 먼저 확정할 대상 선택 규칙

1. R은 활성 배치/붙여넣기 초안 → 명시적 선택 → 커서 아래 단일 대상 순으로 적용한다.
2. M/E는 진행 초안이 없을 때 명시적 선택을 우선한다. 선택이 없으면 커서 아래 대상을 강조하고 동작한다. E는 부품 배치 초안의 속성 편집도 허용한다.
3. W는 선택과 무관하게 커서 아래 연결 가능한 핀/접속점/선분을 우선한다. 배선 진행 중 다시 W를 누르면 현재 초안을 유지한다.
4. 선택 그룹이 있는데 커서가 다른 부품 위에 있어도 M/R/E는 선택 그룹에 적용한다. 상태줄에 대상 수를 표시한다.
5. 후보가 중첩되면 이름·미리보기로 대상을 명확히 하고 선택 팝업을 제공한다. 모호한 상태에서 회로를 바로 변경하지 않는다.
6. Delete, 잘라내기, 복제, 그룹·그룹 해제 같은 편집 명령은 명시적 선택에만 적용한다. Hover만으로 파괴적 명령을 실행하지 않는다.
7. 초안 중 새 도구 A/V/P를 누르면 초안을 폐기하고 요청한 도구로 전환한다. 호환되지 않는 M/F2/복제/시뮬레이션 명령은 실행하지 않고 안내한다.
8. `/` 팔레트로 실행한 명령도 같은 키 명령과 같은 대상 규칙과 안전 규칙을 적용한다. 팔레트가 규칙을 우회하지 않는다. (v0.3)

KiCad의 '선택이 없으면 커서 아래 대상' 방식을 일부 적용한 설계다 [K]. 삭제까지 커서 우선으로 확대하지 않으며, 명령 전에 강조한 대상과 실제 적용 대상이 같아야 한다.

## 7. 웹·한글 입력·키 설정 정책

- 입력·검색·textarea·contenteditable·모달이 활성화되면 도면 단일 키와 편집 명령을 처리하지 않는다. Ctrl+A/C/X/V/Z와 방향키는 입력 UI에 맡긴다.
- 도면은 클릭/키보드 탐색으로 명시적으로 포커스를 얻는다. 마우스가 도면 위에 있다는 이유만으로 다른 입력 필드의 포커스를 빼앗지 않는다.
- 한글 IME 조합 중(isComposing), 조합 시작/끝 경계에서는 도면 명령을 실행하지 않는다 [M]. 단일 영문 명령은 편집기 포커스에서 물리 키 위치(`event.code`)를 기준으로 해 한/영 상태와 무관하게 유지하는 안을 먼저 검증한다. 물리 키 판정만으로 안전하다고 보지 않고, 위의 입력 필드·조합 보호를 함께 적용한다. 다른 키보드 배열에서는 설정 UI에 실제 키를 표시하고 재배정을 허용한다.
- '+'와 '?' 같은 기호는 입력 문자와 숫자패드 키를 별도로 처리한다. Ctrl/Alt/Shift/Meta 조합은 정확히 구분하고, Shift+D가 D나 Ctrl+D로 잘못 처리되지 않게 한다.
- 매핑된 유효 명령을 처리한 경우에만 preventDefault를 적용한다. 잘못된 도구/초안 상태에서의 위험한 편집 키는 안내와 함께 소비한다. Tab은 기본 이동을 유지한다.
- 배치·회전·삭제·실행 토글 등의 keydown 자동 반복은 무시한다. 방향키의 반복 이동만 허용하고 keyup/포커스 상실에서 작업을 마감한다.
- 단축키는 재배정·초기화 가능하게 설계한다. 같은 상태에서 중복 배정하면 저장 전에 충돌을 표시한다. 브라우저 예약키는 경고하며 대체 버튼을 유지한다.
- 문자 하나로 동작하는 명령을 끌 수 있는 설정을 제공한다. 스크린리더·음성 입력과 다른 배열 사용을 함께 검증한다.
- macOS의 Cmd/Option 변환은 별도 프로필에서 검증한다. Windows Ctrl/Alt를 기계적으로 치환해 지원 완료로 주장하지 않는다.

## 9. 검증해야 할 항목

기록 항목은 완료 시간, 오명령, 잘못된 연결, 도구 전환, 도움 요청과 복구 성공 여부다. 결과가 나오기 전에는 특정 세트가 더 빠르거나 조작성이 검증됐다고 표시하지 않는다.

- A→검색→배치→R→W→Shift+Space→연결→M→Esc 흐름을 마우스 메뉴 개입 없이 검사한다.
- **같은 반가산기를 A 검색 / A 검색 보강 / P Place 메뉴로 각각 작성**하고 시간·오입력·학습 시간을 비교한다. A 검색 보강만으로 충분하면 Place 메뉴는 도입하지 않는다.
- 부품을 이동·회전한 뒤 논리 연결이 유지됐는지 확인한다. M의 연결 보존 의미를 KiCad 사용자가 잘 이해하는지 확인한다. 필요하면 별도의 KiCad 호환 프로필(M=연결 없이 이동, G=연결 유지 드래그, 그리드 토글은 다른 키)을 검토하되 기본 의미를 섞지 않는다.
- 배선 중 Shift+Space, Space+드래그, Tab, Esc를 연속 사용해 초안 상태가 예상대로 유지·취소되는지 확인한다. Shift+Space를 누를 때 도면이 이동하거나 페이지가 스크롤되지 않아야 한다. 일반 Tab은 패널로 이동해야 한다.
- 반복 복제에서 간격 재사용, 배치 취소, Undo/Redo를 검사한다.
- 한/영 상태, IME 조합, 입력 필드의 Backspace/Delete/Space/R과 자동 반복을 검사한다. 검색창·속성 필드에서 `/`, `P`, 단일 키가 오명령을 만들지 않는지 확인한다.
- Chrome·Edge·Firefox·내장 브라우저에서 파일 열기/저장/복사 키와 `Ctrl+Enter`, 후보 키(`Ctrl+D`, `Ctrl+G`, `Ctrl+↑/↓`)의 이벤트 수신과 실패 동작을 실제 확인한다. 아직 검사 완료가 아니다.
- Windows 브라우저에서 Alt 단독 입력이 메뉴 포커스를 만들지 않는지 확인한다.
- `Shift+G`(그룹 해제 후보)와 `G`(그리드)의 오조작 빈도를 확인한다.
- 핀 클릭 배선 시작이 핀 선택·이동과 충돌하지 않는지 확인한다.
- 새로운 키 세트와 기존 초안으로 같은 회로를 만드는 시간을 비교한다.

## 10. 열린 결정

1. **M/G의 기본 의미.** v0.3은 M=연결 유지 이동, G=그리드 표시 토글로 잠정 적용한다. KiCad 호환 프로필을 별도로 둘지는 사용성 검사 후 정한다.
2. **Place 메뉴 채택.** 반가산기 비교 결과에 따라 도입 여부와 `P,N` 등 별칭을 정한다.
3. **그룹과 서브회로의 데이터 의미.** 이것이 정해진 뒤에야 `Ctrl+G`, `Ctrl+↓/↑`의 키를 확정하거나 폐기한다.
4. **Step의 의미.** 이벤트 1개와 클록 1주기를 각각 어떤 명령과 키로 둘지 명세가 필요하다.
5. **Input/Output 배치 접근.** 메뉴 항목과 A 검색만으로 충분한지 측정한다.
