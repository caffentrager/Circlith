# Circlith 제품 계획

> **보관 문서 / 구현 기준 아님.** 현재 설계와 구현은 [CIRCLITH_MASTER_SPEC.md](../CIRCLITH_MASTER_SPEC.md)를 우선한다. 아래 내용은 통합 이전의 제안·검토 이력이며, 서로 다른 기본값이나 후보는 현재 명세를 대체하지 않는다.

## 목표와 현재 단계

회로를 빠르게 그리고 연결 상태를 쉽게 이해하며, 실수를 바로 복구할 수 있는 논리회로 시뮬레이션 CAD.

현재 산출물은 설계 문서와 검토용 화면 시안이다. 실행 가능한 회로 편집기나 시뮬레이터는 포함하지 않는다. 일정은 사용성 검증으로 범위가 확정된 뒤 산정한다.

## 사용 환경

- 우선 대상: 논리회로 실습을 하는 학생과 작은 회로를 설명하는 교사. 사용자에게 아직 확인하지 않은 설계 가정이다.
- 우선 입력: Windows 데스크톱의 마우스·키보드. 중간 버튼이 없는 트랙패드도 Space+드래그와 화면 명령으로 조작한다.
- 주 작업: 입력·게이트·출력을 배치하고 연결한 뒤 입력을 바꾸며 결과를 관찰한다.
- 실제 편집 화면은 1024px 이상을 우선 검증한다. 좁은 화면에서는 패널을 접는다. 모바일 터치 편집은 별도 후속 범위다.

## 제품 원칙

1. 클릭 전에 결과를 예상할 수 있어야 한다. 배치, 이동, 연결은 미리보기를 제공한다.
2. 선택·배선·화면 이동을 명확히 구분한다. 빈 공간 드래그는 영역 선택, Space+드래그는 화면 이동이다.
3. 하나의 사용자 의도는 하나의 Undo다. 드래그의 각 프레임을 기록하지 않는다.
4. 핀·접속점·배선의 논리 연결을 유지한다. 좌표가 우연히 같다고 연결을 생성하지 않는다.
5. 사용자 작업을 막는 문제를 먼저 고친다. 큰 라이브러리와 많은 내보내기 형식은 후속 순위다.
6. 상태를 색만으로 전달하지 않는다. 0/1/X/Z 값, 접속점, 경고 표시와 설명을 함께 사용한다.

## 화면안

### 패널형 — 기본 제안

- 상단: 프로젝트 이름, 저장 상태, 선택·배선 도구, Undo/Redo, 실행·정지·Step.
- 왼쪽: 부품 검색, 최근 사용, 기본 논리 부품 목록. 클릭하면 배치 미리보기를 시작한다.
- 중앙: 넓은 도면, 그리드, 핀·배선·선택·미리보기.
- 오른쪽: 선택한 대상의 속성. 선택이 없으면 간단한 조작 안내.
- 하단: 도구 상태와 상황별 키 안내. 파형·진단은 필요할 때 펼친다.

장점은 부품과 속성을 동시에 볼 수 있다는 점이다. 도면 폭이 줄어드는 점을 사용성 검증에서 확인한다.

### 도면 집중형 — 비교안

- 부품 패널을 접고 상단의 부품 추가 버튼 또는 검색 명령으로 연다.
- 속성은 선택한 동안만 오른쪽에 표시한다.
- 파형·진단은 하단에 필요할 때 연다.

장점은 도면 공간이다. 부품 목록을 다시 여는 조작이 추가된다. 시안은 두 안의 공간 차이를 비교하며, 기본안 확정은 사용자 검토 이후로 둔다.

## 범위와 제작 단계

| 단계 | 산출물 | 통과 조건 |
|---|---|---|
| 설계 — 현재 | 조작 명세, 두 화면안, 상태별 피드백, 사용성 시나리오 | 배선·선택·취소 규칙 검토 |
| 편집 프로토타입 | 배치·배선·분기·선택·이동·회전·삭제·Undo/Redo | 반가산기 편집과 취소·복구 흐름 통과 |
| 첫 사용 가능 버전 | AND/OR/NOT/XOR/NAND/NOR/XNOR, 입력·출력, 복사, 저장·복구, 0/1/X/Z 계산, 진단 | 작은 조합회로 실습과 저장 왕복 통과 |
| 시간 시뮬레이션 | D 플립플롭, 클록, Step/Run, 파형 | 동시 이벤트와 상태 초기화 규칙 정의 및 검증 |
| 확장 | Net Label, Probe, 계층 심벌, 추가 순차 소자, 필요 시 파일 호환 | 실제 요구와 재현 가능한 검증 확보 |

첫 버전에서 SPICE, FPGA 제작 흐름, 다비트 버스, 실제 게이트 지연, 클라우드 협업, AI 회로 생성은 다루지 않는다. MyLogic 전체 라이브러리 이식이나 원본 파일 호환도 첫 버전의 조건이 아니다.

## 기술 설계 방향 — 구현 전 가설

- 정적 웹으로 실행 가능한 구조를 기본으로 한다. 로컬 서버는 미리보기 용도이며 기본 실습에 계정은 필요하지 않다.
- 도면 모델, 편집 명령, 입력 제스처, 렌더러, 시뮬레이션 세션, 저장소를 분리한다.
- 연결 모델은 부품 ID·핀 ID·접속 노드·배선 경로를 구분한다. 배선 경로 변경은 전기적 연결을 바꾸지 않는다.
- 화면 확대·이동은 회로 데이터와 분리한다. 포인터 판정은 화면 픽셀, 도면 좌표는 회로 좌표로 관리한다.
- 편집 명령은 트랜잭션으로 확정한다. 미리보기는 저장·Undo·시뮬레이션에 반영하지 않는다.
- 저장 파일은 버전과 안정적인 ID를 포함한다. 검증이 끝난 데이터로만 현재 회로를 교체한다.
- UI 프레임워크와 렌더링 기술은 아직 확정하지 않는다. 핀 판정, 연결 유지, 큰 도면의 응답성을 프로토타입에서 확인한 뒤 결정한다.

## Logic Forge에서 참고할 부분

- core/editor/formats/storage의 책임 분리와 정적 배포 구조.
- 기존 출력·파일·편집 흐름을 고정하는 회귀 검증.
- 실제 브라우저 검증과 Node 기반 논리 검증의 범위 구분.

Circlith는 한 컨트롤러에 상태와 명령을 누적하지 않도록 시작부터 경계를 정의한다. 기존 라이브러리 데이터는 이 계획의 필수 자산이 아니다. 참고 저장소의 기능 지원 주장은 Circlith의 지원 또는 검증 완료를 뜻하지 않는다.

## 검토가 필요한 선택

지금 진행을 막는 필수 질문은 없다. 다음 사항은 시안 검토와 사용자 피드백으로 확정한다.

- 기본 화면은 패널형으로 시작할지, 도면 집중형으로 시작할지.
- 주 사용 환경이 학습용인지 전문 회로 설계용인지.
- 기존 MyLogic 파일을 읽는 기능이 초기 도입의 필수 조건인지.

다음 제작 착수 전에는 화면안과 핵심 조작 규칙에 대한 사용자 피드백을 반영한다.
