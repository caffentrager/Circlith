# Circlith 사용성 검증 계획

> **보관 문서 / 구현 기준 아님.** 현재 설계와 구현은 [CIRCLITH_MASTER_SPEC.md](../CIRCLITH_MASTER_SPEC.md)를 우선한다. 아래 내용은 통합 이전의 제안·검토 이력이며, 서로 다른 기본값이나 후보는 현재 명세를 대체하지 않는다.

현재 문서는 예정된 검사다. 아래 목표 수치는 잠정적인 통과 기준이며 측정 결과가 아니다.

## 검사 방식

프로토타입 준비 후 논리 게이트 개념을 아는 신규 사용자 5명 이상으로 초기 관찰을 진행한다. 기능 사용 경험이 많은 사용자도 별도로 포함한다. 사용자 모집과 검사는 아직 수행하지 않았다.

첫 작업은 설명 없이 시작한다. 막히면 도움을 제공하고 시점·내용을 기록한다. 사용자는 자신이 예상한 클릭 결과를 말하고 관찰자는 실제 결과와 비교한다. 익숙해진 뒤 같은 작업을 반복해 학습 전후 차이를 본다.

각 시나리오에서 완료 시간, 오선택, 의도하지 않은 연결, 취소·Undo 횟수, 도구 전환, 도움 요청과 저장 결과를 기록한다. Undo 자체를 실패로 간주하지 않고 원인을 분류한다. 작은 표본으로 전체 사용자 성능을 일반화하지 않는다.

## 사용자 시나리오

| ID | 작업 | 확인할 내용 | 잠정 기준 |
|---|---|---|---|
| U01 | 입력 2개, XOR·AND, 출력 2개로 반가산기 작성 | 검색→배치→분기→완료 흐름 | 5명 중 4명 이상이 5분 안에 개입 없이 완료 |
| U02 | 이미 연결된 게이트 이동·회전 | 선이 따라오는지, 연결 의도 유지 | 의도하지 않은 단선·접속 0건 |
| U03 | 배선을 잘못 시작하고 경유점 제거·취소 | Backspace와 Esc의 차이 이해 | 확정 회로 변경 0건, 취소 후 바로 다시 시작 가능 |
| U04 | 배선 교차와 분기 생성 | 접속점의 의미 이해 | 교차/접속 판단을 모든 참가자가 설명 가능 |
| U05 | 여러 부품 선택·복사·붙여넣기·이동 | 내부선 복사와 외부선 정책 이해 | 원본 회로 연결 훼손 0건 |
| U06 | 삭제·Undo·Redo 후 다른 편집 | 작업 단위와 Redo 분기 | 원래 구조 완전 복구, 새 편집 후 폐기된 Redo 실행 불가 |
| U07 | 50%·100%·200% 확대에서 핀 연결 | 스냅과 포인터 판정 | 각 확대율에서 10회 중 9회 이상 의도한 핀 선택 |
| U08 | 화면 이동과 영역 선택 반복 | 빈 공간 드래그/Space 드래그 구분 | 반복 10회 중 의도와 다른 제스처 1회 이하 |
| U09 | 입력 전환, 부동 입력·출력 충돌 찾기 | 값·진단과 도면 대상 연결 | 도움 없이 원인 대상 찾기 |
| U10 | 저장·다시 열기·새로고침 복구 | 저장과 자동 복구 차이 | 확정 회로 손실 0건, 저장 실패를 성공으로 표시하지 않음 |

## 상태 무결성 검사

- 배치·이동·영역 선택·배선·붙여넣기 각각에서 Esc, 포커스 상실, 도구 전환을 검사한다.
- 연결 그래프는 이동·회전·선분 이동 전후에 동일해야 한다. 의도한 연결/삭제 명령에서만 변한다.
- Undo/Redo 전후 부품, 경로, 접속 노드, 속성을 비교한다. 선택과 뷰는 별도 정책대로 유지한다.
- 모달·검색·속성 입력 중 Backspace, Delete, Space, V/W/R, Ctrl+A가 도면을 변경하지 않아야 한다.
- 손상 파일, 중복 ID, 없는 핀 참조, 저장소 용량 초과를 재현하고 기존 회로가 유지되는지 확인한다.
- 브라우저 파일 선택·다운로드·포인터 캡처와 실제 레이아웃은 실제 브라우저에서 검사한다. 논리 엔진 검사만으로 대체하지 않는다.

## 응답성 목표

기준 환경은 검사 시작 시 CPU·메모리·브라우저·화면 배율을 기록한다. 다음 수치는 목표이며 기술 선택을 위한 측정 항목이다.

- 100개 부품·200개 배선에서 드래그/배선 미리보기 갱신 p95 33ms 이하.
- 클릭부터 선택 강조 또는 입력 결과 표시까지 p95 100ms 이하.
- 500개 부품·1000개 배선은 스트레스 검사로 별도 기록하고 첫 버전 지원 범위를 결정한다.
- 배치·연결·이동·저장 실패, 의도하지 않은 데이터 손실은 출시 차단 문제로 분류한다.

## 검토 후 남길 기록

화면안, 참가자 환경, 작업 영상 또는 관찰 메모, 시나리오별 결과, 막힌 지점, 수정 결정과 재검사 결과를 남긴다. 사용자 검사 전에는 '사용성이 검증됨'으로 표시하지 않는다.
