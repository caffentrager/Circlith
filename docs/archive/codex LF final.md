## Circlith 통합 설계 문서

작성일: 2026-10-13. Logic Forge 검토, Circlith 제품 계획, 화면 시안, 조작 명세, 단축키 벤치마크와 두 차례 비교 결과를 한 문서로 정리했다.

**Circlith는 회로를 빠르게 그리고, 연결 상태를 쉽게 이해하고, 실수를 바로 복구할 수 있는 논리회로 시뮬레이션 CAD를 목표로 한다. 가장 중요한 평가 기준은 조작성이다.**

현재 단계는 설계다. 앱 구현, 사용자 검사, 실제 브라우저의 편집·파일 입출력 검증은 시작하지 않았다. 이 문서의 final은 현재까지 논의한 내용의 통합본을 의미하며 모든 설계 선택의 사용자 승인이나 검증 완료를 뜻하지 않는다.

## 2. Logic Forge에서 배운 점

Logic Forge는 MyLogic SV5.1의 실습 회로와 심벌을 브라우저에서 편집·시뮬레이션하는 정적 웹 CAD다. 읽은 README에는 심벌 600개, 실습 회로 10개, 라이브러리 넷리스트 523개가 포함된 것으로 설명되어 있다.

핵심 구조는 다음과 같이 파악했다.

- core: 배선·핀 연결망, 기본 소자, 0/1/X/Z 계산, 진리표.
- editor: 부품 변환과 배선 경로, 클립보드.
- simulation/formats/export/storage: 입력 패턴, 파일 형식, 구조 내보내기, 저장.
- ui: 입력 이벤트와 상태 연결, 메뉴·패널·SVG 렌더링. app.js에 여러 책임이 남아 있고 history와 keyboard는 분리됨.

Circlith가 참고할 것은 정적 실행 구조, 책임 분리, 저장 호환과 회귀 검증 방식이다. 기존 지원 범위를 그대로 Circlith의 지원 범위로 선언하지 않는다. MyLogic 데이터와 라이브러리 이식은 초기 개발 조건이 아니며, 이번 작업에서 원본 소스·데이터를 복사하지 않았다.

Logic Forge의 로드맵에서 강조한 편집 안정성, 시뮬레이션 정확성, 저장·원본 호환 검증은 Circlith에도 유효한 개발 원칙이다. 특히 논리 테스트와 실제 브라우저 조작 검증은 서로 대체할 수 없다.

## 3. 제품 목표와 사용자 가정

### 사용 환경

- 우선 입력: Windows 데스크톱의 마우스·키보드. 트랙패드에도 화면 이동 대안을 제공한다.
- 우선 사용자 가정: 논리회로 실습 학생과 작은 회로를 설명하는 교사. 전문 설계 중심인지 여부는 추가 확인 대상이다.
- 대표 작업: 입력·게이트·출력을 배치하고 배선을 연결한 뒤 입력을 바꾸며 결과를 확인한다.
- 화면: 1024px 이상 데스크톱 편집을 먼저 검증한다. 좁은 화면에서는 패널을 접는다. 모바일 터치 편집은 후속 명세 대상이다.
- 기본 실습에는 계정과 운영 서버를 필수로 만들지 않는 정적 웹 구조를 제안한다.

### 조작성의 기준

1. 현재 도구와 다음 클릭의 결과를 알 수 있어야 한다.
2. 부품 배치·이동·배선은 확정 전에 미리보기를 제공한다.
3. 부품과 배선 경로를 이동해도 논리 연결은 유지되어야 한다.
4. 교차·접속·미연결을 명확히 구분한다.
5. 진행 작업은 취소할 수 있고, 확정 작업은 한 번의 Undo로 복구할 수 있어야 한다.
6. 단축키를 외우지 않아도 버튼·메뉴·검색으로 같은 명령에 접근할 수 있어야 한다.
7. 색만으로 신호·선택·오류 의미를 전달하지 않는다.

완료 시간만 줄이는 것이 목표가 아니다. 오선택, 의도하지 않은 연결, 불필요한 도구 전환, 막힌 지점과 복구 성공을 함께 평가한다.

SPICE, FPGA 제작 흐름, 실제 게이트 지연, 클라우드 협업, AI 회로 생성은 첫 버전 범위 밖이다. 원본 MyLogic 전체 라이브러리나 파일 호환도 초기 완료 조건으로 삼지 않는다. 도형·문자·심벌 핀 편집의 장기 필요성을 부정하는 의미는 아니다.

빠른 배치와 명령 팔레트 등의 제안은 프로토타입 검사 결과에 따라 도입한다. 단축키를 예약했다는 이유로 기능 제작 범위를 자동 확대하지 않는다. 개발 일정과 기술 선택은 범위·검증 결과를 보고 산정한다.

## 6. 기본 조작과 상태 전환

| 작업 | 시작 | 완료·확정 | 취소·보존 규칙 |
|---|---|---|---|
| 선택 | V, 대상 클릭 | 선택 대상 강조 | 빈 공간 클릭 또는 선택 대기의 Esc로 해제 |
| 영역 선택 | 선택 도구에서 빈 공간 드래그 | 포인터를 놓으면 대상 확정 | Esc는 이전 선택 복원 |
| 배치 | A 검색·목록에서 부품 선택 | 클릭/Enter로 1개 확정 | Esc는 미리보기 폐기 |
| 연속 배치 | Shift를 누른 채 배치 클릭 | 클릭마다 별도 확정 작업 | Esc는 종료, 이미 놓은 부품 유지 |
| 연결 유지 이동 | 선택 부품 드래그 또는 M | 드래그 놓기, M 이동은 클릭/Enter | Esc는 원래 위치·경로 복원 |
| 회전 | R/Shift+R | 선택 대상에 적용하거나 배치 초안 변환 | 초안 회전은 초안 취소 시 폐기 |
| 배선 대기 | W/도구 버튼 | 핀·선분에서 시작 | Esc는 선택 도구로 복귀 |
| 배선 진행 | 시작 핀 또는 선분 클릭 | 유효한 대상 핀·선분 클릭/Enter | Esc는 초안 취소 후 배선 대기 |
| 선분 이동 | 선택한 배선 선분 드래그 | 직각 경로 확정 | 핀 끝점·논리 연결 유지, Esc는 복원 |
| 붙여넣기·복제 | Ctrl+V/Shift+D | 커서 미리보기 후 클릭/Enter | Esc는 초안 폐기 |
| 화면 이동 | Space+드래그 또는 중간 버튼 드래그 | 놓으면 이전 도구 복귀 | 회로 Undo에 기록하지 않음 |

### 선택

- 클릭은 기존 선택을 교체한다. Shift+클릭은 추가/제거를 토글한다.
- 이미 선택된 부품을 드래그하면 다중 선택 전체를 이동한다. 비선택 부품을 드래그하면 먼저 해당 부품만 선택한다.
- 좌→우 영역은 완전히 포함된 대상, 우→좌 영역은 걸친 대상까지 선택한다. 후보를 미리 강조하고 상태줄에 선택 방식을 표시한다.
- Shift+영역 선택은 현재 선택에 추가한다. Ctrl+A는 도면 전체 편집 대상을 선택한다.
- 빈 공간 드래그는 영역 선택이다. 화면 이동에는 별도의 Space/중간 버튼 제스처를 사용한다.

### 대상 우선순위

- R: 활성 배치/붙여넣기 초안 → 명시적 선택 → 커서 아래 단일 대상.
- M/E: 명시적 선택 우선, 선택이 없으면 커서 아래 대상. E는 배치 초안 속성도 편집할 수 있다.
- W: 선택과 무관하게 커서 아래 연결 가능한 핀·접속점·선분. 빈 공간이면 배선 대기만 시작한다.
- Delete·잘라내기·복제는 명시적 선택에만 적용한다.
- 중첩 후보는 이름·강조·선택 팝업으로 구분하고 모호한 상태에서 바로 변경하지 않는다.
- 선택 그룹이 있으면 커서가 다른 부품 위에 있어도 선택 그룹을 대상으로 한다. 상태줄에 대상 수를 표시한다.

### 취소와 확정

Esc는 가장 가까운 진행 작업부터 취소한다. 도구 전환과 Undo 요청은 진행 미리보기를 먼저 폐기한다. Undo는 이후 마지막 확정 작업을 복구한다. 초안 중 저장은 마지막 확정 회로를 저장하고 초안이 제외됐음을 알린다.

Tab으로 앱 내부 UI를 탐색하는 동안에는 초안을 잠시 유지하고 도면 명령을 멈춘다. 창 비활성화·포인터 캡처 상실은 제스처 롤백으로 처리한다. 자동으로 초안을 확정하지 않는다.

## 7. 배선·스냅·연결 보존

### 배선 흐름

1. 시작 핀 또는 기존 선분 위치를 클릭한다. 선분에서 시작하는 분기 접속점은 완료 전까지 초안이다.
2. 직각 경로 미리보기를 제공하고 빈 공간 클릭으로 경유점을 고정한다.
3. Shift+Space로 마지막 구간의 가로 우선/세로 우선을 바꾼다.
4. Backspace로 마지막 경유점을 제거한다. 시작점만 남으면 초안을 취소한다.
5. 강조된 대상 핀·선분을 클릭하거나 유효 대상에서 Enter로 완료한다.

빈 공간 더블클릭으로 미연결 끝점을 만들 수 있는 초기 제안은 유지하되 중복 경유점이 생기지 않아야 한다. 주 완료 경로는 대상 연결이다. Enter는 대상이 없을 때 미연결 배선을 만들지 않는다.

### 시각 규칙

- 단순 교차는 연결이 아니다. 명시적으로 연결한 접속점에만 점을 표시한다.
- 핀·접속점 스냅 후보는 완료 전에 강조한다.
- 미연결 끝점·부동 입력·다중 드라이버는 도면과 진단에서 찾을 수 있게 한다.
- 출력끼리 연결은 허용하되 즉시 진단하고 값이 충돌하면 X로 표현한다.

### 스냅 초기 가설

핀 반경 9 화면 px, 배선 거리 6 화면 px, 드래그 시작 거리 4 화면 px, 그리드 10 도면 단위를 초기 후보로 둔다. 모두 검증 전 수치다.

판정 거리는 확대율과 무관한 화면 픽셀로 관리하고 도면 좌표와 분리한다. 핀·접속점 스냅이 그리드보다 우선한다. Alt는 그리드만 잠시 해제한다. 좌표가 우연히 겹쳐도 전기적 연결을 새로 만들지 않는다.

### 이동·회전

부품을 옮기거나 회전하면 배선 경로가 핀을 따라간다. 외부 연결과 논리 그래프는 보존하며 연결을 자동 삭제하지 않는다. 겹침은 미리보기·경고로 안내한다. 다중 회전은 표시된 선택 범위 중심을 기준으로 한다.

선분 이동은 연결을 바꾸지 않고 경로만 조정한다. 선택한 선분의 직각 경로를 유지하며 끝점·접속 노드를 고정한다.

## 8. 삭제·클립보드·Undo

- 부품 삭제 후 외부 배선은 남기고 삭제된 핀 쪽 끝점을 미연결로 전환한다. 영향을 미리 표시하며 Undo는 부품·배선 연결을 함께 복구한다.
- 배선 삭제는 해당 경로만 제거한다. 다른 분기는 유지하며 접속 노드 정리는 같은 작업에 포함한다.
- 복사는 선택 부품과 내부 배선을 포함한다. 명시적으로 선택한 외부 배선도 포함하되 복사하지 않은 외부 회로에 붙은 끝점은 미연결로 변환한다.
- 붙여넣기는 새 ID를 부여하고 위치 미리보기 후 확정한다. 잘라내기는 클립보드 기록에 성공한 뒤 삭제한다.
- 이동·회전·배선 완료·선분 이동·삭제·붙여넣기·속성 확정은 각각 하나의 Undo다.
- 방향키 자동 반복은 한 번 누르고 놓는 동안 하나의 이동으로 묶는다. 드래그 프레임은 개별 기록하지 않는다.
- 선택·줌·화면 이동·입력 토글·실행 상태는 회로 구조 Undo와 분리한다.
- 새 편집을 확정하면 Redo 분기를 폐기한다. 초기 100개 기록과 메모리 제한은 검증 후 결정할 가설이다.

## 11. 빠른 배치와 명령 발견의 단계적 설계

### 1단계: A 검색과 별칭

and/nand/in/out/0/1 등 간단한 별칭을 지원하고 Enter로 명확한 검색 결과를 배치 미리보기로 넘긴다.

검색 결과 우선순위는 **정확한 이름·별칭 일치 → 관련 검색 결과 → 최근 사용을 이용한 보조 정렬**로 제안한다. 검색어가 없을 때 최근 사용을 우선 표시한다. 최근 부품을 무조건 첫 결과로 올려 검색어와 다른 부품이 Enter로 선택되는 문제를 방지한다. 첫 결과·선택 결과는 눈에 보이게 강조한다.

### 2단계: 필요하면 Q 배치 메뉴

A 검색과 별칭만으로 반복 작업이 충분하면 도입하지 않는다. Q=Quick place는 실험 후보이고 실제 필요와 효율을 측정한 후 채택한다.

- Q를 누르면 두 번째 키와 대상 이름을 표시한다.
- 1.5초 같은 필수 시간 제한은 두지 않는다. 두 번째 키·항목 클릭·Esc로 종료한다.
- 메뉴가 열린 동안 두 번째 키는 일반 도면 명령보다 우선한다.
- 선택은 부품 생성 완료가 아니라 배치 미리보기 시작이다.
- 초안 중 Q를 누를 때 기존 초안의 취소·전환 규칙도 구현 전에 정의한다.

| 두 번째 키 후보 | 대상 | 근거·유보 |
|---|---|---|
| A / Shift+A | AND / NAND | 기본 게이트와 출력 반전 쌍. 자체 설계 규칙이며 검사 필요 |
| O / Shift+O | OR / NOR | 같은 규칙 |
| X / Shift+X | XOR / XNOR | 같은 규칙 |
| B / Shift+B | Buffer / NOT | 같은 규칙. N=NOT 별칭은 필요성 검증 후 결정 |
| M | MUX | 머릿글자. 소자 지원 시 활성화 |
| F | D 플립플롭 | Flip-flop 연상. 시간 시뮬레이션 단계 후보 |
| C | Clock | 머릿글자. 시간 기능 도입 시 후보 |
| 0 / 1 | 상수 0 / 1 | 값 자체가 대상 |

입력/출력 포트는 명시적 메뉴 항목이나 A 검색으로 먼저 제공한다. I/Shift+I는 후보로만 남기고 출력 버블 반전과 방향 전환을 같은 규칙이라고 설명하지 않는다. 단일 P=Probe 예약과 Q 메뉴는 별개이며 Codex 0.2의 P,P 배정은 이 통합 추천에서는 사용하지 않는다.

### 명령 팔레트와 재실행

/는 모든 명령을 이름으로 찾는 후속 후보다. A는 부품 검색, /는 명령 검색으로 역할을 구분한다. 이름·현재 키·실행 불가 이유를 표시한다. 입력 필드에서는 문자를 그대로 입력한다.

기본 Enter는 확정으로 유지한다. 직전 도구 재실행은 별도 명령 후보로 남기며 빈도·연타·초안/선택 상태의 혼동을 검사한 후 키를 배정한다.

## 12. 후속 기능의 키와 동작

**단순 그룹과 서브회로는 같은 기능이 아니다.** 그룹은 선택·이동 편의를 위한 묶음이다. 서브회로는 외부 포트, 내부 연결, 시뮬레이션 경계와 저장 구조를 가진 단위다. Ctrl+G를 어느 기능에 배정할지 의미와 데이터 모델을 정의한 뒤 결정한다.

정렬·간격 조정은 메뉴/팔레트 우선이다. 간격 반복 복제는 첫 복제의 확정 변위를 다음 미리보기에 재사용하는 기능 후보로 둔다. Ctrl+D 호환키는 북마크 충돌이 있어도 불가능하다고 단정하지 않고 대상 브라우저 검사 후 판단한다.

## 13. 시뮬레이션·편집·저장 정책

### 시뮬레이션

- 첫 버전은 조합회로다. 입력 변화마다 계산하며 시간 실행키가 필요하지 않다.
- 입력 스위치에는 선택과 구분되는 명시적 토글 영역을 제공한다. Space를 입력 토글에 중복 배정하지 않는다.
- 0/1/X/Z는 값과 선 스타일로 표시한다. 진단은 원인 대상 선택·보기 맞춤으로 연결한다.
- 시간 기능 도입 후 구조 편집 확정 전 실행을 정지한다. 새 구조의 상태·시간·파형은 초기화하고 유효한 입력 ID의 현재 값은 유지한다.
- Run은 현재 시점에서 재개, Reset은 t=0으로 초기화한다. Undo로 구조를 복구하면 시뮬레이션도 정지·초기화한다.
- 이벤트 한 단계, 클록 에지 하나, 클록 한 주기는 다른 개념이다. Step은 다음 이벤트를 기본 후보로 두고 정확한 동시 이벤트·클록 정책을 시간 기능 단계에서 명세한다.

### 저장·복구

- JSON 파일은 버전과 안정적인 ID를 포함한다.
- 파일을 읽고 검증한 뒤에만 현재 회로를 교체한다. 손상·중복 ID·없는 핀 참조가 있으면 기존 회로를 유지한다.
- 변경한 도면을 다른 회로로 교체할 때만 저장·폐기·취소 선택을 제공한다.
- 자동 복구는 마지막 확정 편집 이후 저장한다. 브라우저 자동 복구와 명시적 파일 저장의 상태는 구분한다.
- 저장소 실패·용량 초과는 조용히 무시하지 않는다. 원인 안내와 파일 저장 경로를 제공한다.
- 초안·선택·화면 위치와 회로 구조의 저장 범위를 분리한다. 세부 복원 범위는 파일 스키마 확정 때 정의한다.

## 14. 웹 입력·접근성·키 설정

- 도면은 명시적으로 포커스를 얻는다. 마우스가 도면 위라는 이유로 입력창 포커스를 빼앗지 않는다.
- 검색·입력 필드·textarea·contenteditable·모달에서는 도면 단일키와 편집키를 처리하지 않는다.
- 한글 조합 중과 조합 경계에서는 도면 명령을 실행하지 않는다. event.code 물리 키 판정만으로 IME 안전성을 확보했다고 판단하지 않는다.
- 단일 문자키는 물리 위치 기준안을 먼저 검사하고 다른 배열에서는 실제 키 표시·재배정을 제공한다. +/-와 ? 같은 기호·숫자패드·수정키는 별도로 판정한다.
- 회전·삭제·배치·실행 토글의 keydown 자동 반복을 무시한다. 방향키 반복 이동만 의도적으로 허용한다.
- 유효한 앱 명령을 처리한 경우에만 기본 동작을 억제한다. 위험한 편집키는 초안 중 안내와 함께 소비한다. Tab 탐색은 유지한다.
- 같은 상태에서 키가 중복 배정되면 설정 저장 전에 표시한다. 초기화와 단일 문자키 비활성화 설정을 제공한다.
- 모든 주요 기능은 키 외의 버튼·메뉴 경로를 유지한다. 색·Hover만으로 핵심 정보를 전달하지 않는다.
- 완전한 키보드 회로 편집, 스크린리더, 모바일 터치, macOS 키 프로필은 별도 검증 범위이며 현재 지원 완료로 주장하지 않는다.

Chrome 기준 F1 도움말, Ctrl+E 검색, Ctrl+D 북마크, F5 새로고침, F6 탐색, F7 캐럿 탐색 등의 충돌을 검토했다. Ctrl+Enter는 주소창에서 의미가 다르다. 포커스 조건이 전제이며 내장 브라우저·Edge·Firefox는 별도 검증한다. 브라우저가 키를 제공하지 않으면 앱에서 가로챌 수 있다고 보장하지 않는다.

## 15. 기술 설계 방향

구현 기술은 아직 선택하지 않았다. 다음 책임 경계를 권장한다.

| 책임 | 주요 내용 |
|---|---|
| 회로 모델 | 부품·핀·접속 노드·논리 연결·속성·안정적인 ID |
| 도면 경로 | 배선 경유점·부품 배치·변환. 논리 연결과 구분 |
| 편집 명령 | 미리보기·확정 트랜잭션·Undo/Redo |
| 입력 제스처 | 포커스·키·포인터·스냅·상태 전환 |
| 렌더러 | 명시적으로 받은 상태의 도면·선택·신호·미리보기 |
| 시뮬레이션 세션 | 논리 계산·순차 상태·시간·파형. 편집 기록과 구분 |
| 저장 | 파일 검증·버전·자동 복구·오류 처리 |
| UI 연결 | 메뉴·패널·현재 도구. 모든 책임을 단일 controller에 누적하지 않음 |

배선 경로 수정은 논리 연결을 바꾸지 않는다. 미리보기는 확정 회로·저장·시뮬레이션과 분리한다. 렌더링 방식과 프레임워크는 포인터 판정·연결 보존·응답성을 프로토타입에서 확인한 뒤 결정한다.

## 16. 검증 계획과 통과 기준

아래는 목표와 검사 계획이며 수행 결과가 아니다. 초기 관찰은 논리 게이트 개념을 아는 신규 사용자 5명 이상과 기존 CAD 경험자를 대상으로 제안한다. 설명 없이 첫 작업을 시작하고 도움을 제공한 시점을 기록한다. 학습 후 같은 작업도 반복한다.

| 과제 | 확인할 내용 | 잠정 목표 |
|---|---|---|
| 반가산기 작성 | 검색→배치→분기→입력·출력 | 5명 중 4명 이상이 5분 내 개입 없이 완료 |
| 연결된 게이트 이동·회전 | 경로 미리보기와 연결 유지 | 의도하지 않은 단선·접속 0건 |
| 잘못된 배선 취소 | Backspace·Esc 구분 | 확정 회로 손상 없이 재시작 |
| 교차·분기 | 접속점 의미 | 참가자가 연결 여부를 설명 가능 |
| 다중 선택·복사·이동 | 내부/외부 배선 정책 | 원본 회로 연결 손실 0건 |
| 삭제·Undo·Redo | 작업 단위와 분기 폐기 | 구조 완전 복구, 새 편집 후 이전 Redo 실행 불가 |
| 50%·100%·200% 확대 | 핀 스냅 | 각 확대율에서 10회 중 9회 이상 의도한 핀 선택 |
| 영역 선택·화면 이동 | 제스처 구분 | 10회 중 의도와 다른 제스처 1회 이하 |
| 신호·진단 | 부동 입력·충돌 원인 추적 | 도움 없이 원인 대상 찾기 |
| 저장·열기·복구 | 파일과 자동 복구 구분 | 확정 회로 손실 0건, 실패를 성공으로 표시하지 않음 |

### 단축키 비교 검사

- 게이트 20개 이상 배치 과제에서 A 검색, A 별칭·최근 목록, Q 메뉴를 비교한다.
- 필수 시퀀스 시간 제한은 넣지 않는다. 메뉴를 읽고 선택할 때의 오입력과 학습 시간을 기록한다.
- M 연결 보존의 의미를 기존 KiCad 사용자에게 확인한다. 필요하면 별도 호환 프로필을 검사하되 기본 키 의미를 섞지 않는다.
- Shift+Space가 화면 이동·페이지 스크롤을 일으키지 않는지 검사한다.
- Tab으로 UI를 탐색한 뒤 초안 재개·취소가 예상대로 되는지 확인한다.
- 복제의 변위 재사용, 초안 취소, Undo/Redo를 검사한다.
- 한/영 상태·IME 조합·입력창·자동 반복·브라우저 키 수신을 검사한다.
- Alt의 메뉴 포커스, Ctrl+G/계층 키의 수신, Shift+G와 G 오입력을 기능 도입 전에 확인한다.

### 무결성과 응답성

이동·회전·선분 수정 전후 논리 그래프가 같아야 한다. 명시적인 연결·삭제 명령에서만 연결을 변경한다. 취소·캡처 상실·창 비활성화는 중간 데이터 손상을 만들지 않아야 한다.

손상 파일, 중복 ID, 없는 핀 참조, 저장소 용량 초과를 재현한다. 실제 파일 선택·다운로드·포인터·레이아웃은 브라우저에서 검사한다.

기준 CPU·메모리·브라우저·화면 배율을 기록한 뒤 100개 부품·200개 배선에서 미리보기 갱신 p95 33ms 이하, 선택·입력 결과 표시 p95 100ms 이하를 목표로 둔다. 500개 부품·1000개 배선은 별도 스트레스 검사다. 수치는 아직 측정되지 않았다.

완료 시간, 오명령, 잘못된 연결, 도구 전환, 도움 요청과 복구 성공을 기록한다. Undo 사용 자체를 실패로 간주하지 않고 원인을 분류한다. 작은 표본의 결과를 전체 사용자 성능으로 일반화하지 않는다. 데이터 손실·의도하지 않은 연결 변경은 출시 차단 문제다.
