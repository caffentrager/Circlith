> **보관 문서 / 구현 기준 아님.** 현재 설계와 구현은 [CIRCLITH_MASTER_SPEC.md](../CIRCLITH_MASTER_SPEC.md)를 우선한다. 아래 내용은 통합 이전의 제안·검토 이력이며, 서로 다른 기본값이나 후보는 현재 명세를 대체하지 않는다.

작성일: 2026-10-13. 논리회로 시뮬레이션 웹 CAD의 조작성을 위한 설계 제안이다. 앱 구현과 사용자 검증 결과를 의미하지 않는다.

## 비교 대상과 문서 범위

이 문서는 앞서 수행한 다음 두 안의 비교를 정리하고 추천 조합을 제시한다.

- **첨부안:** Circlith_Shortcut_Set_v0.md (원본 미포함)
- **기존 Codex안:** [SHORTCUTS.md — v0.1](SHORTCUTS.md)

사용자가 별도로 제공한 `SHORTCUTS_v0.2.md`는 이번 문서의 참고·병합 대상에서 제외했다. 이 문서의 'Codex 0.2'는 기존 Codex안과 첨부 v0의 비교를 발전시킨 버전이다. 기존 문서의 내용이나 프로젝트 구현을 변경하지 않는다.

## 판단 기준

조작성은 단축키 수나 기존 CAD와 같은 키를 사용하는 비율만으로 판단하지 않는다. 반복 작업을 얼마나 적은 조작으로 수행하는지, 클릭·키 입력의 결과를 예상할 수 있는지, 연결 손실과 오명령을 복구할 수 있는지를 함께 본다.

첨부안은 빠른 배치 시퀀스와 작업 중 상태별 단축키를 적극적으로 제안한다. 기존 Codex안은 연결 유지 이동, 포커스 이동 보존, 초안 취소와 웹 입력 보호에 더 무게를 둔다. 어느 쪽이 실제로 빠른지는 아직 측정하지 않았다.

추천 방향은 **기존 Codex안의 기본 조작에 첨부안의 빠른 배치 메뉴, 명령 팔레트, 간격 반복 복제 기능을 추가하는 것**이다.

## 첨부안에서 도입할 확장

### P 빠른 배치 메뉴

기존 Codex안의 P=Probe 예약은 이 제안에서 변경한다. P는 Place 메뉴를 열고, Probe는 메뉴 안의 P 또는 A 검색으로 접근한다. 이 변경은 빠른 배치 기능을 채택할 때 함께 적용해야 한다.

- P를 누르면 두 번째 키와 대상 이름을 보여주는 메뉴를 연다.
- **1.5초의 필수 시간 제한을 두지 않는다.** 두 번째 키, 항목 클릭 또는 Esc로 종료한다.
- 메뉴가 열린 동안의 두 번째 키는 일반 도면 명령과 구분한다. A는 AND 배치이며 부품 검색창을 열지 않는다.
- 선택한 항목은 곧바로 회로를 변경하지 않고 배치 미리보기를 시작한다.
- Shift를 누른 두 번째 키는 게이트의 출력 반전 쌍에만 사용한다. 입력/출력 포트까지 같은 반전 규칙으로 설명하지 않는다.

| 시퀀스 | 대상 | 근거 및 결정 상태 |
|---|---|---|
| P, A / P, Shift+A | AND / NAND | 같은 기본 게이트와 출력 반전 쌍을 묶는 첨부안의 규칙을 채택 후보로 삼는다. |
| P, O / P, Shift+O | OR / NOR | 같은 규칙. |
| P, X / P, Shift+X | XOR / XNOR | 같은 규칙. |
| P, B / P, Shift+B | Buffer / NOT | 같은 규칙. P, N을 NOT 별칭으로 둘지는 검증한다. |
| P, M | MUX | 대상의 이름을 연상할 수 있는 첨부안 배정. 기능 지원 시 활성화한다. |
| P, F | D 플립플롭 | Flip-flop을 연상할 수 있는 첨부안 배정. 순차회로 지원 시 활성화한다. |
| P, C | Clock | Clock의 첫 글자. 시간 시뮬레이션 단계의 후보. |
| P, 0 / P, 1 | 상수 0 / 1 | 값 자체가 대상 이름이므로 기억하기 쉽다. |
| P, P | Probe | 기존 P 예약을 배치 메뉴 안으로 옮겨 단일 P 충돌을 해소한다. |
| P, S | 서브회로 | 첨부안의 Sub-circuit 배정. 계층 기능 도입 시 검토한다. |

Input/Output의 두 번째 키는 미정으로 남긴다. 첨부안의 P,I / P,Shift+I는 제시된 후보지만 방향 전환과 논리 반전이 다른 개념이다. 초기에는 메뉴의 명시적 입력/출력 항목 또는 A 검색으로 접근한다.

### / 명령 팔레트

명령 이름을 검색하고 실행할 수 있는 경로를 추가한다. A는 부품 찾기, /는 명령 찾기로 역할을 나눈다. 팔레트에는 이름과 현재 배정 키를 함께 표시하고, 현재 상태에서 실행할 수 없는 명령은 이유를 알려준다. 입력 필드에서 /를 입력해도 팔레트를 열지 않는다.

### 간격 반복 복제

첨부안의 같은 간격 반복 복제는 키 배정과 별개로 유용한 기능 후보다. 첫 복제 위치를 확정한 뒤 다음 복제에서 같은 변위를 제안한다. 미리보기를 제공하고 각 확정 복제는 하나의 Undo로 되돌린다.

Ctrl+D는 브라우저 북마크와 겹치지만, 이를 이유로 모든 환경에서 불가능하다고 단정하지 않는다. 앱 포커스에서 실제 이벤트 처리와 실패 동작을 검사한 뒤 호환키 채택 여부를 결정한다. 기본 제안은 Shift+D다.

| Bus | B 예약 | 버스 지원 시 활성화하며 단축키 제안만으로 버스 구현을 앞당기지 않는다. |
| 그룹·서브회로·계층 이동 | 메뉴 우선, 키 미확정 | 첨부안의 Ctrl+G/Shift+G와 Ctrl+↑/↓는 후보로만 둔다. 그룹과 서브회로의 데이터 의미부터 정해야 한다. |
| 정렬·간격 조정 | 메뉴/팔레트 우선 | 첨부안의 Alt 조합은 대상 브라우저와 사용 빈도를 검사한 뒤 채택한다. |
| 직전 도구 재실행 | 별도 명령 후보 | 기본 Enter 확정과 분리한다. 적절한 키는 반복 사용 빈도 검사 후 결정한다. |

## 근거와 표현에서 수정할 사항

1. **같은 키를 쓴다고 학습 비용이 0은 아니다.** 특히 KiCad의 M/G와 Circlith의 연결 유지 M은 의미가 다르다. 기존 관습과 자체 변경을 분리해서 설명한다.
2. **브라우저 충돌은 키와 포커스에 따라 다르다.** Chrome의 F1은 도움말, Ctrl+E는 검색, Ctrl+D는 북마크이며 Ctrl+Enter도 주소창에서 동작한다. '브라우저 예약키와 겹치지 않는다'는 절대 표현을 피한다. [Chrome 공식 단축키](https://support.google.com/chrome/answer/157179?hl=en)
3. **물리 키 판정만으로 IME 안전성을 확보하지 않는다.** event.code와 별도로 입력 필드·조합 상태·포커스 보호가 필요하다. [KeyboardEvent.code](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/code), [isComposing](https://developer.mozilla.org/en-US/docs/Web/API/KeyboardEvent/isComposing)
4. **논리 CAD에 도형이나 핀 편집이 불필요하다고 단정하지 않는다.** 초기 범위에서 제외하는 결정과 장기적인 필요 여부를 구분한다.
5. **P 배치 메뉴는 실제 시간 절약을 검증해야 한다.** 시퀀스 입력, 검색, 최근 부품 선택을 같은 과제로 비교하고 학습 시간과 오입력도 기록한다.

## 프로토타입에서 비교할 과제

- 같은 반가산기를 A 검색과 P 배치 메뉴로 각각 작성한다.
- 부품을 이동·회전한 뒤 논리 연결이 유지됐는지 확인한다.
- 배선 중 Shift+Space, Space+드래그, Tab, Esc를 연속 사용해 초안 상태가 예상대로 유지·취소되는지 확인한다.
- 반복 복제에서 간격 재사용, 배치 취소, Undo/Redo를 검사한다.
- 기존 CAD 사용자와 신규 사용자의 M/G 이해 차이를 기록한다.
- 한글 입력, 검색창, 속성 필드, 브라우저 예약키에서 오명령 여부를 확인한다.

기록 항목은 완료 시간, 오명령, 잘못된 연결, 도구 전환, 도움 요청과 복구 성공 여부다. 결과가 나오기 전에는 특정 세트가 더 빠르거나 조작성이 검증됐다고 표시하지 않는다.
