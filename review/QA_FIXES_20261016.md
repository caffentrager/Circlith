## 후속 승인·해결 — 현재 상태

사용자가 몸체·핀 판정을 설명받은 뒤 추천 정책으로 진행하도록 승인했다. `resolveConnectionHits` 입력 판정에서 초안 없는 SELECT의 직접 몸체 hit만 선택에 양보한다. 실제 surface는 DOM에서 판정하며, 직접 pin hit·몸체 밖 13px 포획·WIRE 도구·배선 초안 연결 판정은 유지한다. pin lead는 몸체 보호에서 제외한다.

QA의 원본 몸체 보호 단위 테스트 한 개는 사용자가 승인한 정책에 맞춰 입력 판정 계층의 직접 body hit를 검사하도록 정정했다. 기대값은 몸체 선택 보호로 유지한다. 저수준 사방 12.9px 포획 테스트와 브라우저 몸체 재현 테스트는 수정하지 않았으며 모두 통과했다. 별도 단위 테스트로 body/직접 pin/빈 공간/배선 의도와 13px 경계를 구분하여 확인했다.

최종 검증: `npm run build` 성공, 단위 **179 통과·1 기본 skip**, 브라우저 **119 통과**. 기존 실패 5개도 해결되어 전체 검증이 통과한다. 아래 보류·실패 수치는 앞선 `4d24b38` 시점 이력으로 보존한다.

꺾임점 삭제 정책도 승인받았다. 끝점·전기적 연결·다른 고정 경유점을 보존하면서 필요한 국소 꺾임 정리와 핀 출입 방향 변경을 허용한다. 이는 기존 구현 동작의 명확화이며 이번에 삭제 알고리즘을 확대하지 않았다. 두 부품 삭제 후 남는 미선택 선 처리만 아직 미확정이다.

## 사용자 요청으로 보류

**P2-1 몸체 클릭과 핀 포획 우선순위는 수정하지 않았다.** 사용자가 설명을 들은 뒤 “우선 다른 버그만 수정”을 선택했다. 기존 핀 포획과 QA의 관련 기대값을 유지한다. 이 때문에 전체 테스트는 아직 통과하지 않으며 Pages 배포 조건도 충족하지 못한다. workflow나 테스트를 우회하지 않는다.

저수준 거리 함수의 13px 포획과 UI의 몸체 클릭 우선순위는 구분할 필요가 있다. 예를 들어 Input 중심 (100,100), 출력 핀 (140,100), zoom 0.25에서 핀 왼쪽 12.9 screen px인 점은 (88.4,100)으로 몸체 내부다. QA의 사방 12.9px 포획 테스트는 이 점을 핀으로 요구한다. 따라서 향후 몸체 우선 정책을 적용할 때는 실제 DOM body hit와 직접 pin hit를 구분하는 입력 계층 테스트를 함께 검토해야 한다. 현재 관련 테스트는 수정하지 않았다.

부품 양쪽을 삭제했을 때 남은 미선택 배선을 함께 지울지, corner 삭제의 핀 출입 방향·이웃 corner 정리 허용 범위는 미확정이다. 사용자가 첫 질문의 의미를 재확인했으며 변경을 승인한 것으로 해석하지 않았다. 기존 동작을 유지한다.
