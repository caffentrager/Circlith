## 5. 다음 작업 패키지와 완료 기준

### T0 — 인수 및 기준선 보존

최신 원격 인계 커밋을 fetch하고 새 작업 브랜치를 만든 뒤 기존 테스트/로그·실행 모드를 확인한다. 로컬에 새 변경이 생겼으면 먼저 보존한다. 변경 후 관련 회귀 검증을 수행한다. 전체 스위트 실행 중 App/CSS 변경이나 Vite가 감시하는 경로에 파일 생성을 병행하면 HMR로 테스트 도면이 초기화될 수 있으므로 피한다. 커밋 단위는 기존 UI 변경과 후속 기능을 구분한다.

### T1 — 다음 우선 구현: 저장·열기·새 도면·자동 복구

**대응:** #24–36, #39–40, #42, #44. #37 특정 API 덮어쓰기, #38 드래그 열기, #41 완전한 다중 탭 편집, #43 손상 파일 부분 수선은 필수로 묶지 않는다.

착수 전 버전 1 문서 envelope, 프로젝트명·회로·뷰 상태·입력값·Undo 이력 포함 여부, unknown version 정책, dirty 기준, 복구 키/탭 충돌·주기·용량 정책을 짧게 명세화한다. 회로/복구/사용자 설정/화면 상태를 구분하고, 초안은 제외한다. 로컬 파일 저장·열기로 동작 가능한 정적 웹 구조를 유지한다.

완료 조건:

1. 프로젝트명·stable ID·핀/net/junction·경로·속성·스키마 버전의 저장→열기 왕복으로 모델 의미와 계산 결과가 보존된다.
2. 전체 parse·형식·참조·geometry 검증을 통과한 뒤에만 현재 문서를 교체한다. 손상·중복 ID·없는 핀·지원하지 않는 버전·실패/취소에서 기존 문서와 편집 기록을 보존한다. migration framework를 위해 가상의 미래 버전 변환을 만들 필요는 없다.
3. 수정된 문서의 열기/새 도면은 Save/Discard/Cancel을 제공하고, Save 실패·취소이면 교체하지 않는다. 새 문서/열기 성공 이후 이력·선택·초안·시뮬 세션 초기화 정책을 명세와 일치시킨다.
4. dirty는 마지막 성공한 명시적 파일 저장 기준을 추적한다. 저장 후 Undo/Redo·이름 변경·저장 실패를 올바르게 표시한다. 다운로드 방식이면 “원본 덮어쓰기 완료”처럼 실제로 알 수 없는 사실을 표시하지 않는다.
5. 마지막 확정 회로의 복구본과 복구 안내·폐기 경로를 제공한다. 손상 복구본·quota·권한/기록 실패를 알리며 현재 작업은 보존한다. 복구 성공은 파일 저장 성공이 아니다.
6. 편집기/시뮬레이션 모드 설정 격리를 유지하며, 회로 문서/복구를 두 모드가 공유할지 분리할지는 명시한다. 입력 프리셋용 Ajv 스키마를 회로 파일 검증으로 재사용했다고 주장하지 않는다.
7. 왕복·실패 원자성·dirty 기준 단위 테스트와 실제 파일 열기/저장·교체 보호·새로고침 복구·저장 실패 브라우저 검증을 통과한다.

모든 FF의 이전 상태 읽기→동시 갱신, 동일 timestamp 이벤트 묶음과 조합 안정화, 편집/Undo/Redo 후 정지·초기화 방향을 검증한다. Step back·조건 정지·setup/hold·모든 FF 변형은 이 목표에 자동 포함하지 않는다. 시뮬 상태를 편집 history에 섞지 않는다.

### T7 — 후속: 구조화와 조건부 확장

Net Label/Probe/Group/Subcircuit/Bus/Text, Mirror·Lock·Replace/Swap·일반 Selection Cycling·고정 net 강조·ERC·미니맵 등은 후속/조건부 단계로 관리한다. 순서·개별 세부는 설계와 필요성에 따라 확정한다. 전기적 연결 범위·파일 ID·포트·폭·인스턴스 상태·변경 전파를 먼저 정의한다.

**조합 Subcircuit 전체가 순차 엔진 이후여야 하는 것은 아니다.** 순차소자를 포함하는 인스턴스 상태 격리는 시간 모델과 연계한다. 추가 소자라는 방향이 #147–154의 전부를 구현하기로 한 약속은 아니다.
