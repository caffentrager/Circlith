# Circlith 범위 내 미구현 기능 목록 (8개 영역 기준)

- 작성일: 2026-10-19 · 대상: `codex/ui-workspace-refresh` 작업 트리 (HEAD `982bf5c` + 미커밋 UI 개편)
- 코드는 수정하지 않았다. 이 문서는 [CAD_FEATURE_GAP_20261019.md](CAD_FEATURE_GAP_20261019.md)(타 CAD 비교 127개)와 달리, **제품 범위 표의 8개 영역 안에서** "목표에 있는데 아직 없는 것"만 다룬다. 타 CAD에 있어도 이 범위 밖이면(MCU, PCB, SPICE 등) 넣지 않았다.

## 0. 증거 표기와 한계

| 표기 | 의미 |
|---|---|
| **[코드]** | 이번 세션에서 해당 소스를 직접 읽고 확인 |
| **[문서]** | Master Spec/README/기타 문서가 후속·미지원으로 명시 |
| **[추정]** | 코드에서 대응 구현을 찾지 못했거나 설계 판단. 실제 동작은 직접 실행해 확인하지 않음 |

한계: 실행해서 조작해 본 것이 아니라 소스 읽기 기반이다. `App.tsx`(1449줄)는 일부만 읽었다. "없다"고 쓴 항목은 해당 기능의 핸들러·UI를 찾지 못했다는 뜻이며, 일부는 다른 경로로 존재할 수 있다. **영향** 열은 "있었을 때 사용자 작업이 얼마나 나아지는가"의 추정이다(상/중/하).

## 1. 이전 문서에서 정정할 내용

이번 조사에서 앞선 두 문서의 주장 중 틀렸거나 낡은 것을 찾았다.

| 앞선 주장 | 실제 | 근거 |
|---|---|---|
| "미저장 변경 경고 없음" (127개 #3) | **이탈 경고(beforeunload)가 있다.** 헤더에 "저장 안 됨 · 새로고침 시 사라짐"도 표시 | `App.tsx:76-82`, `WorkspaceHeader.tsx` |
| "서로 다른 net 배선 겹침 진단 0개" (#112, S0) | **작업 트리에 겹침 경고가 이미 있다** (`wireOverlaps`, 주황 구간, 위치 보기 버튼). 단 미커밋 | `src/geometry/wire-overlaps.ts`, `DrawingWarnings.tsx` |
| "같은 net 전체 선택 없음" (#24) | **`wire.selectNet`이 있다** | `App.tsx` `"wire.selectNet"`, `editor.ts` `selectNet()` |
| "net 하이라이트 없음" (#25) | **선택·호버한 배선/핀의 net을 강조한다.** 없는 것은 *고정* 강조와 부품 선택 시 강조 | `App.tsx` `highlightedNets`, `hoverNet` |
| "배선 분기 명령 없음" | **`wire.branch`, `wire.joinCrossing`, `wire.cleanupDuplicates`가 있다** | `App.tsx` 핸들러 목록 |

→ S0의 "겹침 경고"는 코드는 있고 **커밋·테스트 통과 확인만 남은** 상태다. 앞선 로드맵의 S0을 그만큼 줄여야 한다.

## 비판적 정리

1. **영역 1의 "대부분 구현"은 정확하지만 "완성"은 아니다.** 가장 큰 구멍은 **배선 끝점 재연결(#11)** 이다. 잘못 연결한 배선을 고치려면 지우고 새로 그려야 하고, 이것은 편집기의 핵심 동작이다. 그다음은 Undo 이력의 메모리 구조(#18)로, 회로 전체를 매 편집마다 두 번 복제하므로 큰 회로·긴 세션에서 먼저 문제가 된다.
2. **영역 2는 가장 싸면서 효과가 큰 영역이다.** `assertCircuit`(무결성 검사), `ajv`(스키마), 직렬화 가능한 순수 JSON 모델이 모두 이미 있다. 빠진 것은 포맷·UI·정책뿐이다.
3. **영역 3·4에는 "명령은 등록돼 있고 핸들러만 없는" 항목이 있다.** `clipboard.*`, `commandPalette.open`. 프리셋이 키를 이미 매핑했으므로 사용자는 동작한다고 기대한다.
4. **영역 6·7이 가장 크다.** 영향 '상'이 23개로 전체 51개의 45%인데, 둘은 서로 의존한다(서브회로는 순차 상태 모델 뒤에 정의해야 한다). 이 두 영역은 설계 문서 없이 구현하면 재작업 비용이 크다.
5. **우클릭 메뉴(#76)는 눈에 띄게 얇다.** 문서는 우클릭 메뉴를 주요 기능으로 설명하지만 실제 항목은 4개이고 그 중 둘은 "초안 취소"와 "닫기"다. 클립보드가 생기면 이 메뉴부터 채워야 한다.
6. **영역 8의 가장 큰 공백은 "편집 모드의 ERC(#165)"** 다. 진단 엔진은 시뮬레이션 모드에서만 돌아간다. 편집 모드 사용자는 미연결·다중 구동을 알 수 없다. 겹침 경고(작업 트리에 있음)는 그 일부일 뿐이다.
